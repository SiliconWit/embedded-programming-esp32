## The ESP32 GPIO Matrix

<InArticleAd />


A peripheral is hardware inside the chip that does one job: a PWM generator, a serial port (UART), an SPI bus. On most microcontrollers each peripheral has fixed pins, so two parts that need the same pin mean a new board.

The ESP32 puts a switchboard, the GPIO matrix, between the peripherals and the pins, as an old telephone exchange did between callers. In software you connect almost any peripheral signal to almost any pin, which is why ESP32 projects put PWM, UART and SPI on pins that look freely chosen.

### How Signal Routing Works

```text
 ┌──────────┐    ┌──────────────┐    ┌──────────┐
 │Peripheral│    │  GPIO Matrix │    │ Physical │
 │ Signals  │    │              │    │  Pads    │
 │          │    │ ┌──────────┐ │    │          │
 │ LEDC Ch0 ├───>│ │  Output  │ ├───>│ GPIO 18  │
 │ SPI MOSI ├───>│ │  Matrix  │ ├───>│ GPIO 23  │
 │ UART TX  ├───>│ └──────────┘ │    │          │
 │          │    │ ┌──────────┐ │    │          │
 │ UART RX  │<───┤ │  Input   │ │<───┤ GPIO 16  │
 │ PCNT Sig │<───┤ │  Matrix  │ │<───┤ GPIO 25  │
 │          │    │ └──────────┘ │    │          │
 └──────────┘    └──────────────┘    └──────────┘
  ~25 ns delay per routing stage
```

The matrix keeps two tables, one for each direction. LEDC channel 0 on GPIO18 is one entry in the output table ("this signal goes to pad 18"); the UART receive line on GPIO16 is one entry in the input table ("pad 16 feeds UART RX"). The driver writes these entries when you give it a pin number.

The switchboard costs time: about 25 ns for each pass. For PWM, touch and ordinary inputs and outputs that does not matter. The fastest signals (the SPI flash, the debug port, the fast SD card interface) do not go through the matrix. They have fixed pins.

### GPIO Configuration with `gpio_config()`

A pin used as a plain input or output is set up with `gpio_config()`. You fill a structure with the direction, the pull resistors and the interrupt setting. A pull resistor is a weak internal resistor that holds an input at a known level (high for pull-up, low for pull-down) when nothing drives it.

```c
#include "driver/gpio.h"

gpio_config_t io_conf = {
    .pin_bit_mask = (1ULL << GPIO_NUM_2),   /* Select GPIO2 */
    .mode         = GPIO_MODE_OUTPUT,        /* Output mode */
    .pull_up_en   = GPIO_PULLUP_DISABLE,
    .pull_down_en = GPIO_PULLDOWN_DISABLE,
    .intr_type    = GPIO_INTR_DISABLE,       /* No interrupt */
};
gpio_config(&io_conf);
```

In `pin_bit_mask`, each bit stands for one pin: bit 2 set means GPIO2. To set up several pins in one call, join their bits with the OR operator `|`. For an input, use `.mode = GPIO_MODE_INPUT` and enable a pull-up or pull-down if the signal needs one.

### Pin Limitations

Some pins have a second job that you must not disturb. The most common trap is a strapping pin: a pin that the chip reads once at power-on to decide how to start. If your circuit holds a strapping pin at the wrong level, the board does not boot.

| GPIO Range | Limitation |
|------------|-----------|
| GPIO 34 to 39 | Input only. No internal pull-up or pull-down. Cannot drive outputs. The DevKitC brings out 34, 35, 36 and 39. |
| GPIO 0 | Strapping pin. Directly affects boot mode. Pulled high internally. Avoid using for general I/O unless you understand the boot sequence. |
| GPIO 2 | Strapping pin. Must be low or floating during boot for flash download mode. |
| GPIO 5 | Strapping pin. Sets the timing of the SDIO slave interface at boot. Pulled high internally. |
| GPIO 12 | Strapping pin. Sets flash voltage at boot (low = 3.3V, high = 1.8V). Pulling high can prevent boot on some modules. |
| GPIO 15 | Strapping pin. Controls UART0 debug output at boot. |
| GPIO 6, 7, 8, 9, 10, 11 | Connected to the internal SPI flash. Do not use on modules with a single flash chip (WROOM-32). |

This project uses GPIO18 for the LED and GPIO4 for the touch pad. Neither is a strapping pin.

## LEDC PWM Controller

<InArticleAd />


The mood lamp used 8 bits of resolution: 256 brightness steps. For a dimmer that is too coarse: the eye notices small changes most in dim light, and near the bottom of an 8-bit scale each step is a visible jump. This lesson uses 13 bits: 8192 steps at 5 kHz.

Resolution and frequency share one clock. The timer counts pulses of an 80 MHz clock, and one PWM period must hold at least as many pulses as there are steps. At 5 kHz a period holds 80,000,000 / 5,000 = 16,000 pulses, enough for 8192 steps, so 13 bits fit. A higher frequency leaves fewer pulses per period, so the highest possible resolution falls.

### Timer Groups

LEDC has two groups, high-speed and low-speed, each with four timers and eight channels. Use `LEDC_LOW_SPEED_MODE`: some newer chips of the family (ESP32-S2, ESP32-C3) have no high-speed group, and for dimming an LED you will see no difference.

### Configuration

```c
#include "driver/ledc.h"

#define LEDC_TIMER       LEDC_TIMER_0
#define LEDC_MODE        LEDC_LOW_SPEED_MODE
#define LEDC_CHANNEL     LEDC_CHANNEL_0
#define LEDC_GPIO        18
#define LEDC_FREQUENCY   5000         /* 5 kHz */
#define LEDC_RESOLUTION  LEDC_TIMER_13_BIT  /* 0-8191 duty range */

void ledc_pwm_init(void)
{
    ledc_timer_config_t timer_conf = {
        .speed_mode      = LEDC_MODE,
        .duty_resolution = LEDC_RESOLUTION,
        .timer_num       = LEDC_TIMER,
        .freq_hz         = LEDC_FREQUENCY,
        .clk_cfg         = LEDC_AUTO_CLK,
    };
    ledc_timer_config(&timer_conf);

    ledc_channel_config_t ch_conf = {
        .speed_mode = LEDC_MODE,
        .channel    = LEDC_CHANNEL,
        .timer_sel  = LEDC_TIMER,
        .intr_type  = LEDC_INTR_DISABLE,
        .gpio_num   = LEDC_GPIO,
        .duty       = 0,
        .hpoint     = 0,
    };
    ledc_channel_config(&ch_conf);

    /* Install the fade service (needed for hardware fade functions) */
    ledc_fade_func_install(0);
}
```

Call `ledc_fade_func_install(0)` once before any fade function. It installs the interrupt handler by which the hardware reports a finished fade; the 0 selects the default interrupt settings.

### Hardware Fade Functions

A loop that changes the duty a little, waits and repeats keeps a task busy for the whole fade. LEDC can fade by itself: give it the target duty and the time, and the hardware changes the duty step by step.

```c
/* Fade from current duty to target_duty over 1000 ms */
ledc_set_fade_with_time(LEDC_MODE, LEDC_CHANNEL, target_duty, 1000);
ledc_fade_start(LEDC_MODE, LEDC_CHANNEL, LEDC_FADE_NO_WAIT);
```

With `LEDC_FADE_NO_WAIT` the call returns at once and your task continues while the fade runs. With `LEDC_FADE_WAIT_DONE` the task waits until the fade ends. `ledc_set_fade_with_step()` lets you choose the step size and interval yourself.

### Why Hardware PWM Beats Software PWM

Software PWM switches the pin from your own code. Each time another task or interrupt delays that code, a pulse comes out too long or too short, and the eye sees flicker. LEDC makes the waveform in hardware, so after setup its timing does not depend on what the processor is doing. In low-speed mode with the slow clock it also continues in light sleep, when your code does not run at all.

## Capacitive Touch Sensor

<InArticleAd />


The ESP32 can sense a finger on a bare wire, a copper pad or a track on a circuit board, with no other parts. It does this by measuring capacitance, the ability of a conductor to hold electric charge. Your body holds charge too, so a finger on the pad makes the capacitance larger.

### Touch-Capable GPIOs

Ten GPIOs can sense touch:

| Touch Channel | GPIO |
|--------------|------|
| Touch0 | GPIO 4 |
| Touch1 | GPIO 0 (strapping pin, use with care) |
| Touch2 | GPIO 2 (strapping pin, use with care) |
| Touch3 | GPIO 15 |
| Touch4 | GPIO 13 |
| Touch5 | GPIO 12 (strapping pin, use with care) |
| Touch6 | GPIO 14 |
| Touch7 | GPIO 27 |
| Touch8 | GPIO 33 |
| Touch9 | GPIO 32 |

This project uses Touch0 on GPIO4, which is not a strapping pin.

### How Capacitive Sensing Works

Think of the pad as a bucket that the chip fills with charge and empties, over and over, counting the fills in a fixed time. A finger makes the bucket larger, each fill takes longer, and fewer fills fit in the time.

```text
  no touch                 finger on the pad

  small capacitance        large capacitance
  quick to charge          slow to charge

  ┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐         ┌──┐  ┌──┐  ┌──┐
  ┘└┘└┘└┘└┘└┘└┘└┘└         ┘  └──┘  └──┘  └─

  many cycles counted      few cycles counted
  reading is HIGH          reading is LOW
```

So the number goes down when you touch the pad. Most people expect the opposite, and it sets the direction of every comparison in the code: a touch is a reading below the threshold.

### ESP-IDF Touch API

The touch driver for the original ESP32 is in `driver/touch_pad.h`. The ESP32-S2 and ESP32-S3 have a different touch controller with a different API, so this code is for the original ESP32 only.

```c
#include "driver/touch_pad.h"

void touch_init(void)
{
    /* Initialize the touch pad driver */
    touch_pad_init();

    /* Set the reference voltage for charging and discharging */
    touch_pad_set_voltage(TOUCH_HVOLT_2V7, TOUCH_LVOLT_0V5,
                          TOUCH_HVOLT_ATTEN_1V);

    /* Configure Touch0 (GPIO4) */
    touch_pad_config(TOUCH_PAD_NUM0, 0);

    /* Enable the built-in hardware filter for noise reduction.
       The filter period is in ms. A value of 10 works well. */
    touch_pad_filter_start(10);
}
```

The second argument of `touch_pad_config()` is a threshold. It is 0 here because the firmware measures its own threshold at boot.

### Calibration at Boot

The untouched reading differs for every pad: it changes with the wire length, the pad shape and the humidity. A fixed threshold works on your desk and fails on the next unit. So the firmware reads the pad once at boot, untouched, as the baseline, and sets the threshold as a percentage of it:

```c
#define TOUCH_THRESH_PERCENT  80   /* Touch triggers at 80% of baseline */

static uint16_t touch_threshold;

void touch_calibrate(void)
{
    uint16_t baseline;
    touch_pad_read_filtered(TOUCH_PAD_NUM0, &baseline);

    /* Threshold = 80% of baseline. When touched, the reading
       drops below this value. */
    touch_threshold = baseline * TOUCH_THRESH_PERCENT / 100;

    ESP_LOGI("touch", "Baseline: %d, Threshold: %d", baseline, touch_threshold);
}
```

With a baseline of 523, the threshold is 523 × 80 / 100 = 418 (the division drops the fraction). A reading below 418 counts as a touch.

Call `touch_calibrate()` about 200 ms after `touch_init()`, once the filter has settled. If the lamp switches with no touch, the threshold is too close to the baseline: lower the percentage to 70. If a real touch is missed, raise it to 85. Do not touch the pad while the board starts, or the baseline includes your finger.

### Filtering and Debouncing

Electrical noise can push a reading below the threshold for a moment. The hardware filter (`touch_pad_filter_start()`) smooths the readings. Debouncing is the second defence: a touch counts only after several readings in a row below the threshold, and a release only after several above it. With 3 readings 20 ms apart, a touch is accepted after about 60 ms, which a person does not notice.

```c
#define DEBOUNCE_COUNT  3

static bool is_touched(void)
{
    static int touch_count = 0;
    static int release_count = 0;
    static bool touched = false;

    uint16_t val;
    touch_pad_read_filtered(TOUCH_PAD_NUM0, &val);

    if (val < touch_threshold) {
        touch_count++;
        release_count = 0;
        if (touch_count >= DEBOUNCE_COUNT && !touched) {
            touched = true;
        }
    } else {
        release_count++;
        touch_count = 0;
        if (release_count >= DEBOUNCE_COUNT && touched) {
            touched = false;
        }
    }

    return touched;
}
```

## NVS (Non-Volatile Storage)

<InArticleAd />


A variable in RAM is lost when power is removed, so a lamp that keeps its brightness only there starts dark after every power cut. NVS is the ESP-IDF store for small values that must remain: you save a value under a name (the key) and read it back by that name. It uses the `nvs` partition of the flash, at 0x9000 in the default partition table.

Flash memory wears: each small area survives a limited number of erases, in the order of 100,000. NVS spreads its writes over the whole partition (wear leveling) and keeps the old value safe if power fails during a write. It still wears, so save a value when it changes for good, not many times a second.

### Core API

```c
#include "nvs_flash.h"
#include "nvs.h"

/* Initialize the default NVS partition (call once at startup) */
esp_err_t ret = nvs_flash_init();
if (ret == ESP_ERR_NVS_NO_FREE_PAGES ||
    ret == ESP_ERR_NVS_NEW_VERSION_FOUND) {
    /* NVS partition was corrupted or format changed. Erase and retry. */
    nvs_flash_erase();
    nvs_flash_init();
}

/* Open a namespace (like a folder for keys) */
nvs_handle_t nvs;
nvs_open("lamp", NVS_READWRITE, &nvs);

/* Write a uint8 value */
nvs_set_u8(nvs, "brightness", 128);
nvs_commit(nvs);   /* Flush to flash */

/* Read a uint8 value */
uint8_t brightness;
esp_err_t err = nvs_get_u8(nvs, "brightness", &brightness);
if (err == ESP_ERR_NVS_NOT_FOUND) {
    brightness = 0;  /* Default if key does not exist */
}

/* Close the handle when done */
nvs_close(nvs);
```

Do not forget `nvs_commit()`. Without it the new value may not yet be in flash when power is cut.

NVS stores integers from `u8` to `i64`, strings (`str`) and binary data (`blob`). A key name has at most 15 characters.

### Storing Brightness Across Power Cycles

The dimmer saves the brightness when you lift your finger: once per touch, not once per step of a fade. At boot it reads the saved value and sets the LED to it. On the first boot the key does not exist, so the lamp starts off.

## Circuit Connections

<InArticleAd />


```text
   ESP32 DevKitC
  ┌─────────────┐
  │        GP18 ├──[R1 100R]──┤>├── GND
  │             │              LED
  │         GP4 ├──── Bare wire / copper pad
  │             │     (touch sensor)
  │         GND ├──── GND rail
  │             │
  │     USB     │
  └──────┤├─────┘
```

The LED's long leg (anode) goes through the 100 ohm resistor to GPIO18, and its short leg (cathode) goes to GND.

The touch pad is a bare wire of 5 to 10 cm, or a piece of copper tape, on GPIO4. It needs no resistor. Keep it away from the USB cable and other signal wires, which add noise to the reading.

The resistor sets the LED current: the 3.3 V of the pin, minus the voltage the LED keeps, divided by 100 ohm. For an LED that keeps about 2 V (red, yellow) this is 1.3 V / 100 ohm = 13 mA, near the 12 mA recommended for continuous use of a pin. A white LED keeps about 3 V, so only about 3 mA flows and it is dim. To drive a white LED hard, or an LED strip, switch it with a MOSFET (a transistor used as a switch): gate to GPIO18 through 100 ohm, strip supplied from 5 V or 12 V.

## Complete Firmware

<InArticleAd />


This is the complete `main.c`. One FreeRTOS task reads the pad every 20 ms and decides whether a touch was short or long.

```c
#include <stdio.h>
#include <string.h>

#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "driver/ledc.h"
#include "driver/touch_pad.h"
#include "nvs_flash.h"
#include "nvs.h"
#include "esp_log.h"

static const char *TAG = "touch_lamp";

/* ---------- Pin and PWM configuration ---------- */

#define LED_GPIO         18
#define LEDC_TIMER       LEDC_TIMER_0
#define LEDC_MODE        LEDC_LOW_SPEED_MODE
#define LEDC_CHANNEL     LEDC_CHANNEL_0
#define LEDC_FREQUENCY   5000               /* 5 kHz */
#define LEDC_RESOLUTION  LEDC_TIMER_13_BIT  /* 0-8191 */
#define LEDC_MAX_DUTY    8191

/* ---------- Touch configuration ---------- */

#define TOUCH_PAD_NO          TOUCH_PAD_NUM0   /* GPIO4 */
#define TOUCH_THRESH_PERCENT  80
#define DEBOUNCE_COUNT        3

/* ---------- Timing ---------- */

#define LONG_PRESS_MS     400    /* Hold longer than this to ramp */
#define RAMP_STEP_MS      30     /* Delay between brightness steps */
#define RAMP_STEP_SIZE    64     /* Duty change per step during ramp */
#define FADE_TIME_MS      300    /* Fade duration for toggle on/off */
#define TOUCH_POLL_MS     20     /* Touch polling interval */

/* ---------- NVS ---------- */

#define NVS_NAMESPACE     "lamp"
#define NVS_KEY_BRIGHT    "brightness"

/* ---------- Global state ---------- */

static uint16_t touch_threshold = 0;
static uint16_t current_duty = 0;
static bool lamp_on = false;
static int8_t ramp_direction = 1;   /* 1 = up, -1 = down */

/* ---------- NVS helpers ---------- */

static void nvs_init_storage(void)
{
    esp_err_t ret = nvs_flash_init();
    if (ret == ESP_ERR_NVS_NO_FREE_PAGES ||
        ret == ESP_ERR_NVS_NEW_VERSION_FOUND) {
        nvs_flash_erase();
        nvs_flash_init();
    }
}

static uint16_t nvs_load_brightness(void)
{
    nvs_handle_t nvs;
    uint16_t duty = 0;

    if (nvs_open(NVS_NAMESPACE, NVS_READONLY, &nvs) == ESP_OK) {
        nvs_get_u16(nvs, NVS_KEY_BRIGHT, &duty);
        nvs_close(nvs);
    }

    return duty;
}

static void nvs_save_brightness(uint16_t duty)
{
    nvs_handle_t nvs;
    if (nvs_open(NVS_NAMESPACE, NVS_READWRITE, &nvs) == ESP_OK) {
        nvs_set_u16(nvs, NVS_KEY_BRIGHT, duty);
        nvs_commit(nvs);
        nvs_close(nvs);
    }
}

/* ---------- LEDC helpers ---------- */

static void ledc_pwm_init(void)
{
    ledc_timer_config_t timer_conf = {
        .speed_mode      = LEDC_MODE,
        .duty_resolution = LEDC_RESOLUTION,
        .timer_num       = LEDC_TIMER,
        .freq_hz         = LEDC_FREQUENCY,
        .clk_cfg         = LEDC_AUTO_CLK,
    };
    ledc_timer_config(&timer_conf);

    ledc_channel_config_t ch_conf = {
        .speed_mode = LEDC_MODE,
        .channel    = LEDC_CHANNEL,
        .timer_sel  = LEDC_TIMER,
        .intr_type  = LEDC_INTR_DISABLE,
        .gpio_num   = LED_GPIO,
        .duty       = 0,
        .hpoint     = 0,
    };
    ledc_channel_config(&ch_conf);

    /* Install the fade service for hardware-assisted fading */
    ledc_fade_func_install(0);
}

static void ledc_set_duty_immediate(uint16_t duty)
{
    ledc_set_duty(LEDC_MODE, LEDC_CHANNEL, duty);
    ledc_update_duty(LEDC_MODE, LEDC_CHANNEL);
}

static void ledc_fade_to(uint16_t target_duty, int time_ms)
{
    ledc_set_fade_with_time(LEDC_MODE, LEDC_CHANNEL, target_duty, time_ms);
    ledc_fade_start(LEDC_MODE, LEDC_CHANNEL, LEDC_FADE_WAIT_DONE);
}

/* ---------- Touch helpers ---------- */

static void touch_init_sensor(void)
{
    touch_pad_init();
    touch_pad_set_voltage(TOUCH_HVOLT_2V7, TOUCH_LVOLT_0V5,
                          TOUCH_HVOLT_ATTEN_1V);
    touch_pad_config(TOUCH_PAD_NO, 0);
    touch_pad_filter_start(10);
}

static void touch_calibrate(void)
{
    /* Let the filter settle */
    vTaskDelay(pdMS_TO_TICKS(200));

    uint16_t baseline;
    touch_pad_read_filtered(TOUCH_PAD_NO, &baseline);

    touch_threshold = baseline * TOUCH_THRESH_PERCENT / 100;
    ESP_LOGI(TAG, "Touch calibration: baseline=%d, threshold=%d",
             baseline, touch_threshold);
}

static bool touch_is_active(void)
{
    uint16_t val;
    touch_pad_read_filtered(TOUCH_PAD_NO, &val);
    return (val < touch_threshold);
}

/* ---------- Touch reading task ---------- */

static void touch_task(void *pvParameters)
{
    int debounce_touch = 0;
    int debounce_release = 0;
    bool touched = false;
    bool was_touched = false;
    TickType_t touch_start_tick = 0;
    bool long_press_active = false;

    ESP_LOGI(TAG, "Touch task running on core %d", xPortGetCoreID());

    while (1) {
        /* --- Debounce the raw touch reading --- */
        if (touch_is_active()) {
            debounce_touch++;
            debounce_release = 0;
            if (debounce_touch >= DEBOUNCE_COUNT && !touched) {
                touched = true;
            }
        } else {
            debounce_release++;
            debounce_touch = 0;
            if (debounce_release >= DEBOUNCE_COUNT && touched) {
                touched = false;
            }
        }

        /* --- Detect touch start --- */
        if (touched && !was_touched) {
            touch_start_tick = xTaskGetTickCount();
            long_press_active = false;
        }

        /* --- Long press: ramp brightness while held --- */
        if (touched) {
            TickType_t held_ms = (xTaskGetTickCount() - touch_start_tick)
                                 * portTICK_PERIOD_MS;

            if (held_ms >= LONG_PRESS_MS) {
                if (!long_press_active) {
                    long_press_active = true;
                    /* If the lamp was off, turn it on at minimum brightness */
                    if (!lamp_on) {
                        lamp_on = true;
                        current_duty = RAMP_STEP_SIZE;
                        ledc_set_duty_immediate(current_duty);
                    }
                }

                /* Ramp the brightness */
                int32_t new_duty = (int32_t)current_duty
                                   + ramp_direction * RAMP_STEP_SIZE;

                if (new_duty >= LEDC_MAX_DUTY) {
                    new_duty = LEDC_MAX_DUTY;
                    ramp_direction = -1;  /* Reverse at top */
                } else if (new_duty <= 0) {
                    new_duty = 0;
                    ramp_direction = 1;   /* Reverse at bottom */
                }

                current_duty = (uint16_t)new_duty;
                ledc_set_duty_immediate(current_duty);

                vTaskDelay(pdMS_TO_TICKS(RAMP_STEP_MS));
                was_touched = touched;
                continue;
            }
        }

        /* --- Touch release: decide short or long --- */
        if (!touched && was_touched) {
            if (!long_press_active) {
                /* Short touch: toggle on/off */
                if (lamp_on) {
                    /* Fade to off */
                    ledc_fade_to(0, FADE_TIME_MS);
                    current_duty = 0;
                    lamp_on = false;
                    ESP_LOGI(TAG, "Lamp OFF");
                } else {
                    /* Restore saved brightness, or default to 50% */
                    uint16_t saved = nvs_load_brightness();
                    if (saved == 0) {
                        saved = LEDC_MAX_DUTY / 2;
                    }
                    ledc_fade_to(saved, FADE_TIME_MS);
                    current_duty = saved;
                    lamp_on = true;
                    ESP_LOGI(TAG, "Lamp ON, duty=%d", current_duty);
                }
            } else {
                /* Long press just ended: save the new brightness */
                ESP_LOGI(TAG, "Ramp ended, saving duty=%d", current_duty);
                if (current_duty == 0) {
                    lamp_on = false;
                }
            }

            /* Save brightness to NVS (only if on) */
            if (lamp_on) {
                nvs_save_brightness(current_duty);
            }

            /* Reverse ramp direction for next long press */
            ramp_direction = -ramp_direction;
        }

        was_touched = touched;
        vTaskDelay(pdMS_TO_TICKS(TOUCH_POLL_MS));
    }
}

/* ---------- Entry point ---------- */

void app_main(void)
{
    ESP_LOGI(TAG, "Capacitive Touch Lamp Dimmer starting");

    /* Initialize NVS */
    nvs_init_storage();

    /* Initialize LEDC PWM (13-bit, 5 kHz) */
    ledc_pwm_init();

    /* Restore brightness from NVS */
    uint16_t saved_duty = nvs_load_brightness();
    if (saved_duty > 0) {
        current_duty = saved_duty;
        lamp_on = true;
        ledc_set_duty_immediate(current_duty);
        ESP_LOGI(TAG, "Restored brightness: %d", current_duty);
    }

    /* Initialize touch sensor and calibrate */
    touch_init_sensor();
    touch_calibrate();

    /* Create the touch reading task */
    xTaskCreatePinnedToCore(
        touch_task,
        "touch_task",
        4096,
        NULL,
        5,
        NULL,
        1       /* Run on APP_CPU to avoid Wi-Fi/system task contention */
    );

    /* app_main returns; the touch task keeps running */
}
```

### How the Code Works

The helper functions are the pieces you have already seen: NVS load and save, LEDC setup, touch setup and calibration. The new part is `touch_task`. Every 20 ms it debounces the reading, measures how long the pad has been held, and chooses one of two actions:

- A touch shorter than 400 ms switches the lamp. The hardware fade takes 300 ms. When the lamp switches on, it returns to the saved brightness.
- A touch of 400 ms or longer changes the brightness by 64 duty steps every 30 ms while you hold. The full range of 8191 takes 128 steps, about 3.8 seconds. The direction reverses at the top and bottom of the range, and each time you release.

On every release with the lamp on, the brightness is saved to NVS.

### Adjusting Touch Sensitivity

If the lamp switches with no touch, try these in order:

1. Lower `TOUCH_THRESH_PERCENT` from 80 to 70 or 65.
2. Increase `DEBOUNCE_COUNT` from 3 to 5.
3. Shorten the touch wire. Long wires pick up more noise.
4. Keep the wire away from the USB cable and power lines.

If the sensor does not respond at all, check that the wire is on GPIO4, and read the baseline in the serial output. For a short wire it is usually 400 to 700. A baseline near zero means a wiring fault.

## Pulse Counter and RMT Overview

<InArticleAd />


Two more peripherals count and time fast pulses in hardware, which software does badly. The dimmer does not use them, but you will meet them.

### Pulse Counter (PCNT)

Some sensors send their value as pulses: a flow meter gives one pulse per amount of water, a rotary encoder gives pulses as a shaft turns. Software that counts them misses pulses whenever it is busy; PCNT counts the edges in hardware. A second pin can set the direction of counting. Its uses:

- Rotary encoders. The two signals of the encoder go to the two inputs, and the counter goes up for one direction of rotation and down for the other.
- Frequency measurement. Count the rising edges in a known time.
- Event counting, such as pulses from a flow meter.

The ESP32 has 8 PCNT units. Each has a signed 16-bit counter and limits that raise an interrupt when the count reaches them. The driver is `driver/pulse_cnt.h`:

```c
#include "driver/pulse_cnt.h"

/* Create a PCNT unit */
pcnt_unit_config_t unit_config = {
    .high_limit = 100,
    .low_limit  = -100,
};
pcnt_unit_handle_t pcnt_unit = NULL;
pcnt_new_unit(&unit_config, &pcnt_unit);

/* Create a channel on that unit */
pcnt_chan_config_t chan_config = {
    .edge_gpio_num  = GPIO_NUM_25,    /* Signal input */
    .level_gpio_num = GPIO_NUM_26,    /* Direction control (optional) */
};
pcnt_channel_handle_t pcnt_chan = NULL;
pcnt_new_channel(pcnt_unit, &chan_config, &pcnt_chan);
```

You then choose what each edge does (count up, count down or nothing) for each level of the direction pin.

### RMT (Remote Control Transceiver)

RMT sends and receives trains of pulses whose lengths are exact. It was made for infrared remote controls, and it serves any protocol that carries its data in pulse lengths:

- WS2812 (NeoPixel) addressable LEDs, which need exact timing at 800 kHz.
- Infrared remote control, sending and receiving (NEC, RC5 and others).
- DHT11 and DHT22 temperature sensors, whose bits differ only in the length of a pulse.

The ESP32 has 8 RMT channels, and each can transmit or receive. The drivers are `driver/rmt_tx.h` and `driver/rmt_rx.h`. An encoder turns your data into RMT symbols, which are pairs of pulses with a set length and level:

```c
#include "driver/rmt_tx.h"

rmt_tx_channel_config_t tx_config = {
    .gpio_num           = GPIO_NUM_18,
    .clk_src            = RMT_CLK_SRC_DEFAULT,
    .resolution_hz      = 10000000,  /* 10 MHz, 100 ns per tick */
    .mem_block_symbols  = 64,
    .trans_queue_depth  = 4,
};
rmt_channel_handle_t tx_chan = NULL;
rmt_new_tx_channel(&tx_config, &tx_chan);
```

The rule behind LEDC, PCNT and RMT is the same: when timing must be exact, let hardware do it, and let your code decide what should happen.

## Exercises

<InArticleAd />


1. **Add a second touch pad for mode selection.** Wire a second bare wire to GPIO27 (Touch7). Touch0 still controls brightness; a short touch on Touch7 cycles through three modes: solid on, slow pulse (brightness ramps up and down in a loop) and off. You need a second set of debounce variables and a mode state machine.

2. **Implement exponential dimming.** The eye sees brightness on a logarithmic scale, so linear PWM steps look uneven (the low end changes too fast, the high end looks flat). Replace the linear ramp with a gamma-corrected curve: a lookup table of 256 entries, `table[i] = (int)(pow(i / 255.0, 2.8) * 8191)`, that maps a linear 0 to 255 brightness to a 13-bit duty. Compare the smoothness with the linear ramp.

3. **Log touch events with timestamps.** In the touch task, call `esp_timer_get_time()` and log each touch and release with the raw filtered reading, the threshold and the milliseconds since boot. Measure the real debounce delay and check it against `DEBOUNCE_COUNT * TOUCH_POLL_MS`.

4. **Store and recall multiple brightness presets.** Save three preset brightness levels in NVS under the keys "preset0", "preset1", "preset2". A triple-tap (three short touches within 1 second) saves the current brightness to the next preset slot; a double-tap recalls the next stored preset. Log the active preset number.

## Summary

<InArticleAd />


- The GPIO matrix connects almost any peripheral signal to almost any pin. Strapping pins, input-only pins and the flash pins are the exceptions.
- LEDC resolution and frequency share one clock: a higher frequency leaves fewer steps.
- A touch makes the reading fall. Measure the baseline at boot, set the threshold as a percentage of it, and debounce.
- NVS keeps small values through a power cut. Commit each write, and do not write many times a second.
- PCNT counts pulses and RMT times them, both in hardware.
