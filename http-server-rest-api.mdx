A heater with only a dial on the wall tells you nothing. To know the room temperature, or to change the target, somebody must walk to it. A display and buttons cost parts, and a phone app must be installed by every user. A small web server inside the device avoids all of this: any phone or laptop on the same network becomes the control panel. In this lesson you build a thermostat that reads a temperature sensor, switches a relay, and serves its own web page at `thermostat.local`. The thermostat decides by itself, in its firmware. The page only shows what it does and changes its target. #ESP32 #HTTPServer #IoT

## Circuit Connections

<InArticleAd />


```text
 ┌──────────────┐
 │   ESP32      │
 │         GP4  ├──┬──[R1 4.7K]── 3.3V
 │              │  │
 │              │  └── DHT22 Data
 │              │      DHT22 VCC ── 3.3V
 │              │      DHT22 GND ── GND
 │              │
 │         GP5  ├───── Relay IN (active low)
 │              │      Relay VCC ── 5V (VBUS)
 │              │      Relay GND ── GND
 │              │      Relay COM/NO ── Load
 │              │
 │     USB      │      thermostat.local
 └──────┤├──────┘      (mDNS, port 80)
```

The DHT22 has four pins. With the grille facing you, from left to right: VCC, Data, NC (not connected) and GND. Put the 4.7k resistor between Data and 3.3 V. The sensor and the ESP32 only ever pull this line low, and the resistor pulls it high again. Without it the readings fail.

A relay is a switch moved by an electromagnet (the coil). Most relay modules accept the 3.3 V signal of the ESP32 on the IN pin but need 5 V for the coil. The DevKitC gives 5 V on its VBUS pin when it is powered by USB. If your module has separate VCC and JD-VCC pins, connect VCC to 3.3 V and JD-VCC to 5 V. On a module with one VCC pin at 5 V, a high of 3.3 V on IN may not switch its input LED fully off: check that the relay really releases when IN is high, before you trust it. The output terminals (COM, NO, NC) are the switch contacts.

:::caution[Test with a low voltage load]
For this lesson, listen for the click of the relay, or switch an LED with its resistor from a low voltage supply. Connecting a mains heater to the relay is work for a licensed electrician, and a breadboard relay module is not built for it.
:::

## ESP-IDF HTTP Server

<InArticleAd />


HTTP is the language of browsers and web servers: the browser sends a request that names a method and an address, and the server sends back a response. Two methods are enough here: GET asks for something, and POST sends data to change something. The address after the host name, such as `/api/status`, is the URI.

ESP-IDF's small HTTP server, `esp_http_server`, runs as a FreeRTOS task, accepts the connections and reads the requests. You write one handler function for each method and URI you want to answer.

### Starting the Server

`httpd_start()` creates the server from a configuration structure:

```c
#include "esp_http_server.h"

static httpd_handle_t server = NULL;

static httpd_handle_t start_webserver(void)
{
    httpd_config_t config = HTTPD_DEFAULT_CONFIG();
    config.uri_match_fn = httpd_uri_match_wildcard;
    config.stack_size   = 8192;

    if (httpd_start(&server, &config) == ESP_OK) {
        /* Register URI handlers here */
        return server;
    }

    return NULL;
}
```

`HTTPD_DEFAULT_CONFIG()` gives port 80, at most 8 URI handlers and 7 connections at once. Setting `uri_match_fn` to `httpd_uri_match_wildcard` allows a pattern with `*`, such as `/static/*`, to match many addresses. The file handler needs this.

### Registering URI Handlers

An endpoint is one method and URI that the server answers. Each is described by an `httpd_uri_t` structure:

```c
static esp_err_t status_get_handler(httpd_req_t *req)
{
    /* Build and send a JSON response */
    const char *resp = "{\"temp\":22.5}";
    httpd_resp_set_type(req, "application/json");
    httpd_resp_sendstr(req, resp);
    return ESP_OK;
}

httpd_uri_t status_uri = {
    .uri      = "/api/status",
    .method   = HTTP_GET,
    .handler  = status_get_handler,
    .user_ctx = NULL,
};

httpd_register_uri_handler(server, &status_uri);
```

The handler receives the request as an `httpd_req_t` pointer. It sets the content type with `httpd_resp_set_type()` and sends the body with `httpd_resp_sendstr()` for text or `httpd_resp_send()` for data of a given length. The server adds the status line and the headers.

### Reading POST Request Bodies

A POST request carries data in its body. The server does not read the body for you. The handler reads it into its own buffer with `httpd_req_recv()`:

```c
static esp_err_t setpoint_post_handler(httpd_req_t *req)
{
    char buf[128];
    int received = httpd_req_recv(req, buf, sizeof(buf) - 1);
    if (received <= 0) {
        httpd_resp_send_err(req, HTTPD_400_BAD_REQUEST, "Empty body");
        return ESP_FAIL;
    }
    buf[received] = '\0';

    /* Parse buf as JSON and process the setpoint */
    /* ... */

    httpd_resp_sendstr(req, "{\"status\":\"ok\"}");
    return ESP_OK;
}
```

`httpd_req_recv()` returns the number of bytes read, 0 if the connection closed, or a negative value on error. The body is not a C string: put a zero byte at its end before passing it to a function that expects one. Never trust the body: anyone on the network can send anything, so limit the length and check every value.

## REST API Design

<InArticleAd />


REST is a plain agreement about how to use HTTP for data: an address names a thing, GET reads it, and POST changes it. A program can then use the device as easily as a person uses the page.

```text
 ┌──────────┐  HTTP GET /api/status  ┌──────────┐
 │ Browser  ├───────────────────────>│  ESP32   │
 │          │                        │ HTTP Srv │
 │          │  200 OK + JSON body    │          │
 │          │<───────────────────────┤  DHT22   │
 │          │  {"temp":22.5,         │  Relay   │
 │          │   "humidity":45.2,     │  SPIFFS  │
 │          │   "setpoint":23.0}     │          │
 └──────────┘                        └──────────┘
  Phone/Laptop                       192.168.x.x
  thermostat.local                   (mDNS)
```

The thermostat has three endpoints. All data is JSON, a text format of names and values inside braces:

| Method | URI | Purpose | Request Body | Response Body |
|--------|-----|---------|-------------|---------------|
| GET | `/api/status` | Read current state | (none) | `{"temp":22.5, "humidity":45.2, "setpoint":23.0, "relay":true, "mode":"auto"}` |
| POST | `/api/setpoint` | Change target temperature | `{"setpoint":25.0}` | `{"status":"ok", "setpoint":25.0}` |
| POST | `/api/mode` | Change operating mode | `{"mode":"manual_on"}` | `{"status":"ok", "mode":"manual_on"}` |

### Operating Modes

The thermostat has three modes:

- `auto`, the default: the firmware compares the temperature with the setpoint and switches the relay.
- `manual_on`: the relay is on whatever the temperature. In this mode nothing limits the temperature, so use it for tests only.
- `manual_off`: the relay is off. The setpoint is kept.

### CORS Headers

A browser blocks a page loaded from one server from sending requests to another, unless the second server permits it. While you develop, a page opened from a file on your computer is blocked from the ESP32. The server permits it with a CORS header on each response:

```c
httpd_resp_set_hdr(req, "Access-Control-Allow-Origin", "*");
```

The `*` permits pages from anywhere. That is acceptable on a bench. This API also has no login: anyone on the same network can change the setpoint. A product must name the permitted origins and ask for a password.

## JSON with cJSON

<InArticleAd />


Building JSON text by hand with `snprintf` works for one value and breaks with the first forgotten quote. ESP-IDF includes the cJSON library, which builds JSON from values and parses JSON back into values.

### Building a JSON Response

```c
#include "cJSON.h"

static char *build_status_json(float temp, float humidity,
                               float setpoint, bool relay_on,
                               const char *mode)
{
    cJSON *root = cJSON_CreateObject();
    cJSON_AddNumberToObject(root, "temp", temp);
    cJSON_AddNumberToObject(root, "humidity", humidity);
    cJSON_AddNumberToObject(root, "setpoint", setpoint);
    cJSON_AddBoolToObject(root, "relay", relay_on);
    cJSON_AddStringToObject(root, "mode", mode);

    char *json_str = cJSON_PrintUnformatted(root);
    cJSON_Delete(root);

    return json_str;  /* Caller must free() this */
}
```

`cJSON_PrintUnformatted()` returns the JSON as one compact string (`cJSON_Print()` adds spaces and line breaks for human readers). The string is new memory: call `free()` on it after sending, and `cJSON_Delete()` on the object. Forget, and each request loses a little memory until, after some hours, none is left.

### Parsing a JSON Request

```c
static float parse_setpoint(const char *json_str)
{
    cJSON *root = cJSON_Parse(json_str);
    if (root == NULL) {
        return -1.0f;  /* Parse error */
    }

    cJSON *sp = cJSON_GetObjectItem(root, "setpoint");
    float value = -1.0f;
    if (cJSON_IsNumber(sp)) {
        value = (float)sp->valuedouble;
    }

    cJSON_Delete(root);
    return value;
}
```

Check the type with `cJSON_IsNumber()`, `cJSON_IsString()` or `cJSON_IsBool()` before you use a value. If the name is missing or the type is wrong, the check is false: send an error response and change nothing.

## SPIFFS Filesystem

<InArticleAd />


The web page is a file that must live somewhere. HTML inside a C string means a new firmware build for every change to the page. SPIFFS (SPI Flash File System) is a small file system in its own flash partition: the page is an ordinary file there, which you can replace without touching the C code.

### Partition Table

The default partition table has no place for files, so the project needs its own. Create `partitions.csv` in the project root:

```
# Name,   Type, SubType,  Offset,   Size
nvs,       data, nvs,     0x9000,   0x6000
phy_init,  data, phy,     0xf000,   0x1000
factory,   app,  factory, 0x10000,  0x180000
storage,   data, spiffs,  0x190000, 0x70000
```

The program gets 0x180000 bytes (1.5 MB) from 0x10000, so it ends at 0x190000, exactly where `storage` begins. `storage` is 0x70000 bytes (448 KB). You need these two numbers again when you write the file image to the flash.

Select this table in `idf.py menuconfig`:
- **Partition Table** > **Partition Table** > **Custom partition table CSV**
- **Partition Table** > **Custom partition CSV file** > `partitions.csv`

Or add these lines to `sdkconfig.defaults`:

```
CONFIG_PARTITION_TABLE_CUSTOM=y
CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="partitions.csv"
```

### Initializing SPIFFS

```c
#include "esp_spiffs.h"

static esp_err_t init_spiffs(void)
{
    esp_vfs_spiffs_conf_t conf = {
        .base_path              = "/spiffs",
        .partition_label        = "storage",
        .max_files              = 5,
        .format_if_mount_failed = true,
    };

    esp_err_t ret = esp_vfs_spiffs_register(&conf);
    if (ret != ESP_OK) {
        ESP_LOGE("spiffs", "Failed to mount SPIFFS (%s)",
                 esp_err_to_name(ret));
        return ret;
    }

    size_t total = 0, used = 0;
    esp_spiffs_info("storage", &total, &used);
    ESP_LOGI("spiffs", "SPIFFS: total=%d, used=%d", total, used);

    return ESP_OK;
}
```

Mounting connects the partition to a path. After it, the standard C functions `fopen()`, `fread()` and `fclose()` work on files under `/spiffs/`, so `/spiffs/index.html` is the file `index.html` in the partition.

### Serving Static Files

A static file is one that is sent as it is. This handler opens the file and sends it in pieces:

```c
static esp_err_t static_file_handler(httpd_req_t *req)
{
    char filepath[64];
    const char *uri = req->uri;

    /* Default to index.html for root */
    if (strcmp(uri, "/") == 0) {
        uri = "/index.html";
    }

    snprintf(filepath, sizeof(filepath), "/spiffs%s", uri);

    FILE *f = fopen(filepath, "r");
    if (f == NULL) {
        httpd_resp_send_err(req, HTTPD_404_NOT_FOUND, "File not found");
        return ESP_FAIL;
    }

    /* Set content type based on file extension */
    if (strstr(uri, ".html")) {
        httpd_resp_set_type(req, "text/html");
    } else if (strstr(uri, ".css")) {
        httpd_resp_set_type(req, "text/css");
    } else if (strstr(uri, ".js")) {
        httpd_resp_set_type(req, "application/javascript");
    } else {
        httpd_resp_set_type(req, "text/plain");
    }

    char buf[512];
    size_t read_bytes;
    while ((read_bytes = fread(buf, 1, sizeof(buf), f)) > 0) {
        httpd_resp_send_chunk(req, buf, read_bytes);
    }
    fclose(f);

    /* End chunked response */
    httpd_resp_send_chunk(req, NULL, 0);
    return ESP_OK;
}
```

This handler is registered with the pattern `/*`, which matches every address. The server tries handlers in the order of registration, so register it last. If it came first, it would also take the requests meant for the API.

## mDNS Discovery

<InArticleAd />


The router gives the thermostat an IP address, perhaps a different one next week; a name is easier to remember and does not change. On the internet DNS servers turn names into addresses, but no DNS server on your local network knows your device. With mDNS (multicast DNS) the device answers for its own name: a browser asks the whole local network "who is `thermostat.local`?", and the ESP32 replies with its address.

### Initializing mDNS

```c
#include "mdns.h"

static void init_mdns(void)
{
    mdns_init();
    mdns_hostname_set("thermostat");
    mdns_instance_name_set("ESP32 Thermostat");

    /* Advertise the HTTP service so discovery tools can find it */
    mdns_service_add(NULL, "_http", "_tcp", 80, NULL, 0);

    ESP_LOGI("mdns", "mDNS hostname: thermostat.local");
}
```

After `mdns_hostname_set("thermostat")` the ESP32 answers to `thermostat.local`. `mdns_service_add()` is optional: it announces that the device has a web server, so that tools such as `avahi-browse` or `dns-sd -B _http._tcp` can list it.

### Platform Notes

mDNS works on macOS, and on Linux if Avahi is installed. On Windows 10 and 11, recent versions of Chrome and Edge resolve `.local` names. If `thermostat.local` is not found, install Apple's Bonjour Print Services for Windows, or use the IP address from the boot log. The name works only inside the local network.

### Adding mDNS to the Build

Since ESP-IDF v5.0 the mDNS component is no longer shipped inside the framework. Download it from the component registry once, from the project folder:

```bash
idf.py add-dependency "espressif/mdns"
```

This writes `main/idf_component.yml`, and the next build fetches the component. Then add `mdns` to the component requirements in `main/CMakeLists.txt`:

```cmake
idf_component_register(SRCS "main.c"
                       INCLUDE_DIRS "."
                       REQUIRES esp_http_server
                                spiffs
                                mdns
                                nvs_flash
                                json)
```

The `json` component provides cJSON. It is included in ESP-IDF by default but listing it explicitly makes the dependency clear.

## DHT22 Sensor Reading

<InArticleAd />


The DHT22 sends its reading on one wire with no clock line, so the information is in the timing: a short high pulse is a 0 and a long one is a 1. The ESP32 asks for a reading by pulling the line low for at least 1 ms. The sensor answers with 40 bits: 16 for humidity, 16 for temperature and 8 for a checksum.

### Protocol Timing

1. The ESP32 pulls the line low for 1 to 10 ms, then releases it.
2. The sensor answers: low for 80 µs, then high for 80 µs.
3. For each of the 40 bits, the sensor pulls the line low for 50 µs and then lets it go high. The length of the high pulse is the bit.

```text
            bit 0                    bit 1
           ┌──┐                   ┌───────┐
  ─┐       │  │        ─┐         │       │
   └───────┘  └─        └─────────┘       └─
    50 µs  27 µs          50 µs     70 µs

  the code decides at 40 µs:  shorter = 0, longer = 1
```

The checksum is the last 8 bits of the sum of the four data bytes. If one bit was read wrongly, the sum does not match and the whole reading is rejected. A rejected reading is far better than a wrong temperature.

### Bit-Banging Implementation

Bit-banging means that the program reads the pin itself and measures the times, with no dedicated hardware. Here `esp_timer_get_time()` gives the time in microseconds:

```c
#include "driver/gpio.h"
#include "esp_timer.h"
#include "esp_rom_sys.h"

#define DHT_GPIO    GPIO_NUM_4
#define DHT_TIMEOUT 1000  /* Timeout in microseconds */

typedef struct {
    float temperature;
    float humidity;
    bool valid;
} dht_reading_t;

static int dht_wait_for_level(int level, int timeout_us)
{
    int64_t start = esp_timer_get_time();
    while (gpio_get_level(DHT_GPIO) != level) {
        if ((esp_timer_get_time() - start) > timeout_us) {
            return -1;  /* Timeout */
        }
    }
    return (int)(esp_timer_get_time() - start);
}

static dht_reading_t dht_read(void)
{
    dht_reading_t result = { .valid = false };
    uint8_t data[5] = {0};

    /* --- Host start signal --- */
    gpio_set_direction(DHT_GPIO, GPIO_MODE_OUTPUT);
    gpio_set_level(DHT_GPIO, 0);
    esp_rom_delay_us(2000);               /* Hold low for 2 ms (shorter than
                                             one tick at the default 100 Hz) */
    gpio_set_level(DHT_GPIO, 1);

    /* Switch to input to read sensor response */
    gpio_set_direction(DHT_GPIO, GPIO_MODE_INPUT);

    /* --- Wait for sensor response --- */
    if (dht_wait_for_level(0, DHT_TIMEOUT) < 0) return result;
    if (dht_wait_for_level(1, DHT_TIMEOUT) < 0) return result;
    if (dht_wait_for_level(0, DHT_TIMEOUT) < 0) return result;

    /* --- Read 40 bits --- */
    for (int i = 0; i < 40; i++) {
        /* Wait for the sync pulse (low) to end */
        if (dht_wait_for_level(1, DHT_TIMEOUT) < 0) return result;

        /* Measure how long the data pulse (high) lasts */
        int high_us = dht_wait_for_level(0, DHT_TIMEOUT);
        if (high_us < 0) return result;

        /* If high for more than 40 us, it is a '1' */
        data[i / 8] <<= 1;
        if (high_us > 40) {
            data[i / 8] |= 1;
        }
    }

    /* --- Verify checksum --- */
    uint8_t checksum = data[0] + data[1] + data[2] + data[3];
    if (checksum != data[4]) {
        ESP_LOGW("dht", "Checksum mismatch: computed=%d, received=%d",
                 checksum, data[4]);
        return result;
    }

    /* --- Decode humidity and temperature --- */
    result.humidity = ((data[0] << 8) | data[1]) / 10.0f;

    int16_t raw_temp = ((data[2] & 0x7F) << 8) | data[3];
    if (data[2] & 0x80) {
        raw_temp = -raw_temp;  /* Negative temperature */
    }
    result.temperature = raw_temp / 10.0f;

    result.valid = true;
    return result;
}
```

Do not read the DHT22 more often than once every 2 seconds. It needs that time to make a new measurement.

### Critical Section Considerations

The margin is small: a 0 lasts about 27 µs and the code decides at 40 µs. Anything that takes the processor for more than about 13 µs during a 0 makes it measure longer than 40 µs, so it is read as a 1, the checksum fails, and the reading is rejected. The sensor task runs on core 1, so the Wi-Fi interrupts on core 0 do not reach it, but the tick interrupt and other tasks that may run on core 1 at the same priority (the HTTP server is not pinned) still can. A failed reading is normal: the sensor task tries again 2 seconds later, and most readings succeed.

You could turn interrupts off for the 5 ms of the 40 bits with a critical section (`portENTER_CRITICAL()`). On the ESP32 that stops only core 1, and Wi-Fi on core 0 continues; on a one-core chip of the family, such as the ESP32-C3, it would stop Wi-Fi and lose packets. The robust answer is the RMT receiver, which measures the pulse lengths in hardware (see the RMT overview in the [GPIO and peripherals lesson](/education/embedded-programming-esp32/gpio-peripherals-driver-framework/)).

A broken sensor wire must not leave the heater on. The firmware counts failed readings in a row, and after 5 (10 seconds) it marks the temperature as unknown (`NAN`) and, in auto mode, switches the relay off. Until a good reading returns, auto mode holds it off, because every comparison with `NAN` is false. Software is still not enough: a heater must always have its own thermal cut-out that does not depend on any software.

## Relay Control and Hysteresis

<InArticleAd />


Most relay modules are active low: the relay switches on when the ESP32 pulls the IN pin low, and off when the pin is high. So the code writes 0 for on and 1 for off, and it writes 1 first at start, so that the heater is off until the thermostat decides.

### GPIO Configuration

```c
#define RELAY_GPIO  GPIO_NUM_5

static void relay_init(void)
{
    gpio_config_t io_conf = {
        .pin_bit_mask = (1ULL << RELAY_GPIO),
        .mode         = GPIO_MODE_OUTPUT,
        .pull_up_en   = GPIO_PULLUP_DISABLE,
        .pull_down_en = GPIO_PULLDOWN_DISABLE,
        .intr_type    = GPIO_INTR_DISABLE,
    };
    gpio_config(&io_conf);
    gpio_set_level(RELAY_GPIO, 1);  /* Start with relay OFF (active low) */
}

static void relay_set(bool on)
{
    gpio_set_level(RELAY_GPIO, on ? 0 : 1);  /* Active low */
}
```

### Why Hysteresis Matters

The simplest rule, "heater on below the setpoint, off above it", fails near the setpoint. With a setpoint of 23.0 °C, sensor noise gives readings such as 22.9, 23.1, 22.9, and the relay can switch at every reading, once every 2 seconds. A mechanical relay is good for about 100,000 operations, so it would be worn out within days.

Hysteresis uses two switching points in place of one. With `HYSTERESIS` set to 0.5 °C and a setpoint of 23.0 °C:

- the relay switches on when the temperature falls below 23.0 minus 0.5, which is 22.5 °C;
- the relay switches off when the temperature rises above 23.0 plus 0.5, which is 23.5 °C;
- between 22.5 and 23.5 °C the relay keeps the state it has.

```text
 23.5 ─ ─ ─ ─ ─ ╱╲─ ─ ─ ─ ─ ─ ╱╲─ ─ ─   off above this
               ╱  ╲          ╱  ╲
 23.0         ╱    ╲        ╱    ╲       setpoint
             ╱      ╲      ╱      ╲
 22.5 ─ ─ ─ ╱─ ─ ─ ─ ╲─ ─ ╱─ ─ ─ ─ ╲─   on below this

 heater:  ON     OFF     ON     OFF
```

The band is 1.0 °C wide. Noise of 0.2 °C can no longer switch the relay: the temperature must cross the whole band before the relay changes again. Think of a door with a latch: a light push does not open it, and once open it stays open until you push it firmly shut. The price is that the room moves 0.5 °C to each side of the setpoint.

## Thermostat Logic

<InArticleAd />


This function is the whole controller. It runs on the ESP32 every 2 seconds, after each good reading, and it needs no network. If the Wi-Fi fails, the page stops and the thermostat does not.

```c
#define HYSTERESIS  0.5f

typedef enum {
    MODE_AUTO,
    MODE_MANUAL_ON,
    MODE_MANUAL_OFF,
} thermostat_mode_t;

typedef struct {
    float temperature;
    float humidity;
    float setpoint;
    bool relay_on;
    thermostat_mode_t mode;
    SemaphoreHandle_t mutex;
} thermostat_state_t;

static thermostat_state_t state;

static void thermostat_update(void)
{
    xSemaphoreTake(state.mutex, portMAX_DELAY);

    switch (state.mode) {
    case MODE_AUTO:
        if (state.temperature < (state.setpoint - HYSTERESIS)) {
            state.relay_on = true;
        } else if (state.temperature > (state.setpoint + HYSTERESIS)) {
            state.relay_on = false;
        }
        /* Between the bounds, relay holds its current state */
        break;

    case MODE_MANUAL_ON:
        state.relay_on = true;
        break;

    case MODE_MANUAL_OFF:
        state.relay_on = false;
        break;
    }

    relay_set(state.relay_on);

    xSemaphoreGive(state.mutex);
}
```

Two tasks use the `state` structure: the sensor task writes the temperature, and the HTTP server task reads the state and writes the setpoint and mode. Each takes the mutex (a lock that one task holds at a time) before it touches `state`, so a response is never built from a half-updated structure.

```c
static EventGroupHandle_t wifi_event_group;
#define WIFI_CONNECTED_BIT  BIT0
#define WIFI_FAIL_BIT       BIT1

static int wifi_retry_count = 0;

static void wifi_event_handler(void *arg, esp_event_base_t base,
                               int32_t event_id, void *event_data)
{
    if (base == WIFI_EVENT && event_id == WIFI_EVENT_STA_START) {
        esp_wifi_connect();
    } else if (base == WIFI_EVENT &&
               event_id == WIFI_EVENT_STA_DISCONNECTED) {
        if (wifi_retry_count < WIFI_MAX_RETRY) {
            esp_wifi_connect();
            wifi_retry_count++;
            ESP_LOGI(TAG, "Retrying Wi-Fi connection (%d/%d)",
                     wifi_retry_count, WIFI_MAX_RETRY);
        } else {
            xEventGroupSetBits(wifi_event_group, WIFI_FAIL_BIT);
        }
    } else if (base == IP_EVENT && event_id == IP_EVENT_STA_GOT_IP) {
        ip_event_got_ip_t *event = (ip_event_got_ip_t *)event_data;
        ESP_LOGI(TAG, "Connected. IP: " IPSTR,
                 IP2STR(&event->ip_info.ip));
        wifi_retry_count = 0;
        xEventGroupSetBits(wifi_event_group, WIFI_CONNECTED_BIT);
    }
}

static void wifi_init_sta(void)
{
    wifi_event_group = xEventGroupCreate();

    ESP_ERROR_CHECK(esp_netif_init());
    ESP_ERROR_CHECK(esp_event_loop_create_default());
    esp_netif_create_default_wifi_sta();

    wifi_init_config_t cfg = WIFI_INIT_CONFIG_DEFAULT();
    ESP_ERROR_CHECK(esp_wifi_init(&cfg));

    esp_event_handler_instance_t instance_any_id;
    esp_event_handler_instance_t instance_got_ip;

    ESP_ERROR_CHECK(esp_event_handler_instance_register(
        WIFI_EVENT, ESP_EVENT_ANY_ID,
        &wifi_event_handler, NULL, &instance_any_id));
    ESP_ERROR_CHECK(esp_event_handler_instance_register(
        IP_EVENT, IP_EVENT_STA_GOT_IP,
        &wifi_event_handler, NULL, &instance_got_ip));

    wifi_config_t wifi_config = {
        .sta = {
            .ssid     = WIFI_SSID,
            .password = WIFI_PASS,
            .threshold.authmode = WIFI_AUTH_WPA2_PSK,
        },
    };

    ESP_ERROR_CHECK(esp_wifi_set_mode(WIFI_MODE_STA));
    ESP_ERROR_CHECK(esp_wifi_set_config(WIFI_IF_STA, &wifi_config));
    ESP_ERROR_CHECK(esp_wifi_start());

    ESP_LOGI(TAG, "Connecting to %s ...", WIFI_SSID);

    EventBits_t bits = xEventGroupWaitBits(
        wifi_event_group,
        WIFI_CONNECTED_BIT | WIFI_FAIL_BIT,
        pdFALSE, pdFALSE, portMAX_DELAY);

    if (bits & WIFI_CONNECTED_BIT) {
        ESP_LOGI(TAG, "Wi-Fi connected");
    } else {
        ESP_LOGE(TAG, "Wi-Fi connection failed");
    }
}

/* ================================================================
 * DHT22 Sensor
 * ================================================================ */

typedef struct {
    float temperature;
    float humidity;
    bool valid;
} dht_reading_t;

static int dht_wait_for_level(int level, int timeout_us)
{
    int64_t start = esp_timer_get_time();
    while (gpio_get_level(DHT_GPIO) != level) {
        if ((esp_timer_get_time() - start) > timeout_us) {
            return -1;
        }
    }
    return (int)(esp_timer_get_time() - start);
}

static dht_reading_t dht_read(void)
{
    dht_reading_t result = { .valid = false };
    uint8_t data[5] = {0};

    /* Host start signal: pull low for 2 ms, then release */
    gpio_set_direction(DHT_GPIO, GPIO_MODE_OUTPUT);
    gpio_set_level(DHT_GPIO, 0);
    esp_rom_delay_us(2000);   /* 2 ms is less than one tick at 100 Hz */
    gpio_set_level(DHT_GPIO, 1);
    gpio_set_direction(DHT_GPIO, GPIO_MODE_INPUT);

    /* Sensor response: low 80 us, high 80 us */
    if (dht_wait_for_level(0, DHT_TIMEOUT_US) < 0) return result;
    if (dht_wait_for_level(1, DHT_TIMEOUT_US) < 0) return result;
    if (dht_wait_for_level(0, DHT_TIMEOUT_US) < 0) return result;

    /* Read 40 bits */
    for (int i = 0; i < 40; i++) {
        if (dht_wait_for_level(1, DHT_TIMEOUT_US) < 0) return result;
        int high_us = dht_wait_for_level(0, DHT_TIMEOUT_US);
        if (high_us < 0) return result;

        data[i / 8] <<= 1;
        if (high_us > 40) {
            data[i / 8] |= 1;
        }
    }

    /* Verify checksum */
    uint8_t checksum = data[0] + data[1] + data[2] + data[3];
    if ((checksum & 0xFF) != data[4]) {
        ESP_LOGW(TAG, "DHT checksum error");
        return result;
    }

    /* Decode values */
    result.humidity = ((data[0] << 8) | data[1]) / 10.0f;

    int16_t raw_temp = ((data[2] & 0x7F) << 8) | data[3];
    if (data[2] & 0x80) {
        raw_temp = -raw_temp;
    }
    result.temperature = raw_temp / 10.0f;
    result.valid = true;

    return result;
}

static void relay_init(void)

/* ================================================================
 * Thermostat State
 * ================================================================ */

typedef enum {
    MODE_AUTO,
    MODE_MANUAL_ON,
    MODE_MANUAL_OFF,
} thermostat_mode_t;

static const char *mode_to_str(thermostat_mode_t m)
{
    switch (m) {
    case MODE_AUTO:       return "auto";
    case MODE_MANUAL_ON:  return "manual_on";
    case MODE_MANUAL_OFF: return "manual_off";
    default:              return "auto";
    }
}

static thermostat_mode_t str_to_mode(const char *s)
{
    if (strcmp(s, "manual_on") == 0)  return MODE_MANUAL_ON;
    if (strcmp(s, "manual_off") == 0) return MODE_MANUAL_OFF;
    return MODE_AUTO;
}

typedef struct {
    float             temperature;
    float             humidity;
    float             setpoint;
    bool              relay_on;
    thermostat_mode_t mode;
    SemaphoreHandle_t mutex;
} thermostat_state_t;

static thermostat_state_t state;

static void state_init(void)
{
    /* NAN means "no valid reading yet". Every comparison with NAN is
       false, so auto mode cannot switch the heater on before the first
       good reading (0.0 would read as "cold" and switch it on). */
    state.temperature = NAN;
    state.humidity    = NAN;
    state.setpoint    = DEFAULT_SETPOINT;
    state.relay_on    = false;
    state.mode        = MODE_AUTO;
    state.mutex       = xSemaphoreCreateMutex();
}

static void thermostat_update(void)
{
    xSemaphoreTake(state.mutex, portMAX_DELAY);

    switch (state.mode) {
    case MODE_AUTO:
        if (state.temperature < (state.setpoint - HYSTERESIS)) {
            state.relay_on = true;
        } else if (state.temperature > (state.setpoint + HYSTERESIS)) {
            state.relay_on = false;
        }
        break;
    case MODE_MANUAL_ON:
        state.relay_on = true;
        break;
    case MODE_MANUAL_OFF:
        state.relay_on = false;
        break;
    }

    relay_set(state.relay_on);
    xSemaphoreGive(state.mutex);
}

/* GET /api/status */
static esp_err_t api_status_handler(httpd_req_t *req)
{
    xSemaphoreTake(state.mutex, portMAX_DELAY);

    cJSON *root = cJSON_CreateObject();
    cJSON_AddNumberToObject(root, "temp", state.temperature);
    cJSON_AddNumberToObject(root, "humidity", state.humidity);
    cJSON_AddNumberToObject(root, "setpoint", state.setpoint);
    cJSON_AddBoolToObject(root, "relay", state.relay_on);
    cJSON_AddStringToObject(root, "mode", mode_to_str(state.mode));

    xSemaphoreGive(state.mutex);

    char *json = cJSON_PrintUnformatted(root);
    cJSON_Delete(root);

    httpd_resp_set_type(req, "application/json");
    httpd_resp_set_hdr(req, "Access-Control-Allow-Origin", "*");
    httpd_resp_sendstr(req, json);
    free(json);

    return ESP_OK;
}

/* POST /api/setpoint */
static esp_err_t api_setpoint_handler(httpd_req_t *req)
{
    char buf[128];
    int received = httpd_req_recv(req, buf, sizeof(buf) - 1);
    if (received <= 0) {
        httpd_resp_send_err(req, HTTPD_400_BAD_REQUEST, "Empty body");
        return ESP_FAIL;
    }
    buf[received] = '\0';

    cJSON *root = cJSON_Parse(buf);
    if (root == NULL) {
        httpd_resp_send_err(req, HTTPD_400_BAD_REQUEST, "Invalid JSON");
        return ESP_FAIL;
    }

    cJSON *sp = cJSON_GetObjectItem(root, "setpoint");
    if (!cJSON_IsNumber(sp)) {
        cJSON_Delete(root);
        httpd_resp_send_err(req, HTTPD_400_BAD_REQUEST,
                            "Missing setpoint field");
        return ESP_FAIL;
    }

    float new_sp = (float)sp->valuedouble;
    cJSON_Delete(root);

    /* Clamp to a reasonable range */
    if (new_sp < 10.0f) new_sp = 10.0f;
    if (new_sp > 35.0f) new_sp = 35.0f;

    xSemaphoreTake(state.mutex, portMAX_DELAY);
    state.setpoint = new_sp;
    xSemaphoreGive(state.mutex);

    ESP_LOGI(TAG, "Setpoint changed to %.1f C", new_sp);

    /* Respond with confirmation */
    cJSON *resp = cJSON_CreateObject();
    cJSON_AddStringToObject(resp, "status", "ok");
    cJSON_AddNumberToObject(resp, "setpoint", new_sp);
    char *json = cJSON_PrintUnformatted(resp);
    cJSON_Delete(resp);

    httpd_resp_set_type(req, "application/json");
    httpd_resp_set_hdr(req, "Access-Control-Allow-Origin", "*");
    httpd_resp_sendstr(req, json);
    free(json);

    return ESP_OK;
}

/* POST /api/mode */
static esp_err_t api_mode_handler(httpd_req_t *req)
{
    char buf[128];
    int received = httpd_req_recv(req, buf, sizeof(buf) - 1);
    if (received <= 0) {
        httpd_resp_send_err(req, HTTPD_400_BAD_REQUEST, "Empty body");

    }
    buf[received] = '\0';

    cJSON *root = cJSON_Parse(buf);
    if (root == NULL) {
        httpd_resp_send_err(req, HTTPD_400_BAD_REQUEST, "Invalid JSON");
        return ESP_FAIL;
    }

    cJSON *mode_item = cJSON_GetObjectItem(root, "mode");

        cJSON_Delete(root);
        httpd_resp_send_err(req, HTTPD_400_BAD_REQUEST,

        return ESP_FAIL;

    xSemaphoreGive(state.mutex);

    ESP_LOGI(TAG, "Mode changed to %s", mode_to_str(new_mode));

    /* Immediately apply the new mode */
    thermostat_update();

    cJSON *resp = cJSON_CreateObject();
    cJSON_AddStringToObject(resp, "status", "ok");
    cJSON_AddStringToObject(resp, "mode", mode_to_str(new_mode));
    char *json = cJSON_PrintUnformatted(resp);
    cJSON_Delete(resp);

    httpd_resp_set_type(req, "application/json");
    httpd_resp_set_hdr(req, "Access-Control-Allow-Origin", "*");
    httpd_resp_sendstr(req, json);
    free(json);

    return ESP_OK;
}

{
    char filepath[64];
    const char *uri = req->uri;

    if (strcmp(uri, "/") == 0) {
        uri = "/index.html";
    }

    snprintf(filepath, sizeof(filepath), "/spiffs%s", uri);

    FILE *f = fopen(filepath, "r");
    if (f == NULL) {
        httpd_resp_send_err(req, HTTPD_404_NOT_FOUND, "File not found");
        return ESP_FAIL;
    }

    if (strstr(uri, ".html")) {
        httpd_resp_set_type(req, "text/html");
    } else if (strstr(uri, ".css")) {
        httpd_resp_set_type(req, "text/css");
    } else if (strstr(uri, ".js")) {
        httpd_resp_set_type(req, "application/javascript");
    } else {
        httpd_resp_set_type(req, "text/plain");
    }

    httpd_resp_set_hdr(req, "Access-Control-Allow-Origin", "*");

    char chunk[512];
    size_t read_bytes;
    while ((read_bytes = fread(chunk, 1, sizeof(chunk), f)) > 0) {
        httpd_resp_send_chunk(req, chunk, read_bytes);
    }
    fclose(f);

    httpd_resp_send_chunk(req, NULL, 0);
    return ESP_OK;
}

/* ================================================================
 * HTTP Server: Start and Register Handlers
 * ================================================================ */

static httpd_handle_t start_webserver(void)
{
    httpd_config_t config = HTTPD_DEFAULT_CONFIG();
    config.uri_match_fn = httpd_uri_match_wildcard;
    config.stack_size   = 8192;

    httpd_handle_t server = NULL;
    if (httpd_start(&server, &config) != ESP_OK) {
        ESP_LOGE(TAG, "Failed to start HTTP server");
        return NULL;
    }

    /* API endpoints (register before the wildcard catch-all) */
    httpd_uri_t status_uri = {
        .uri     = "/api/status",
        .method  = HTTP_GET,
        .handler = api_status_handler,
    };
    httpd_register_uri_handler(server, &status_uri);

    httpd_uri_t setpoint_uri = {
        .uri     = "/api/setpoint",
        .method  = HTTP_POST,
        .handler = api_setpoint_handler,
    };
    httpd_register_uri_handler(server, &setpoint_uri);

    httpd_uri_t mode_uri = {
        .uri     = "/api/mode",
        .method  = HTTP_POST,
        .handler = api_mode_handler,
    };
    httpd_register_uri_handler(server, &mode_uri);

    /* Static file handler (wildcard, must be last) */
    httpd_uri_t static_uri = {
        .uri     = "/*",
        .method  = HTTP_GET,
        .handler = static_file_handler,
    };
    httpd_register_uri_handler(server, &static_uri);

    ESP_LOGI(TAG, "HTTP server started on port 80");
    return server;
}

/* ================================================================
 * Sensor Task
 * ================================================================ */

static void sensor_task(void *pvParameters)
{
    ESP_LOGI(TAG, "Sensor task started on core %d", xPortGetCoreID());
    int failures = 0;   /* failed readings in a row */

    while (1) {
        dht_reading_t reading = dht_read();

        if (reading.valid) {
            failures = 0;
            xSemaphoreTake(state.mutex, portMAX_DELAY);
            state.temperature = reading.temperature;
            state.humidity    = reading.humidity;
            xSemaphoreGive(state.mutex);

            /* Run the control logic first so the log shows the new relay state */
            thermostat_update();

            ESP_LOGI(TAG, "Temp=%.1f C  Humidity=%.1f %%  "
                     "Setpoint=%.1f  Relay=%s  Mode=%s",
                     reading.temperature, reading.humidity,
                     state.setpoint,
                     state.relay_on ? "ON" : "OFF",
                     mode_to_str(state.mode));
        } else {
            ESP_LOGW(TAG, "DHT read failed, skipping cycle");
            if (++failures == 5) {   /* 10 s with no good reading */
                xSemaphoreTake(state.mutex, portMAX_DELAY);
                state.temperature = NAN;   /* auto mode now holds off */
                if (state.mode == MODE_AUTO) {
                    state.relay_on = false;
                    relay_set(false);
                }
                xSemaphoreGive(state.mutex);
                ESP_LOGE(TAG, "No valid reading for 10 s: heater off");
            }
        }

        vTaskDelay(pdMS_TO_TICKS(SENSOR_READ_MS));
    }
}

/* ================================================================
 * Entry Point
 * ================================================================ */

void app_main(void)
{
    ESP_LOGI(TAG, "ESP32 Thermostat starting");

    /* Initialize NVS (required by Wi-Fi) */
    esp_err_t ret = nvs_flash_init();
    if (ret == ESP_ERR_NVS_NO_FREE_PAGES ||
        ret == ESP_ERR_NVS_NEW_VERSION_FOUND) {
        nvs_flash_erase();
        nvs_flash_init();
    }

    /* Initialize thermostat state */
    state_init();

    /* Initialize relay (off by default) */
    relay_init();

    /* Connect to Wi-Fi */
    wifi_init_sta();

    /* Initialize mDNS */
    init_mdns();

    /* Mount SPIFFS filesystem */
    init_spiffs();

    /* Start the HTTP server */
    start_webserver();

    /* Start the sensor reading task */
    xTaskCreatePinnedToCore(
        sensor_task,
        "sensor_task",
        4096,
        NULL,
        5,
        NULL,
        1   /* Run on APP_CPU */
    );

    ESP_LOGI(TAG, "System ready. Open http://thermostat.local");
}
```

### How the Code Works

The firmware has six parts:

1. `wifi_init_sta()` joins the access point and waits until the connection succeeds or fails. The SSID and password come from menuconfig (`CONFIG_WIFI_SSID` and `CONFIG_WIFI_PASSWORD`).

2. `init_spiffs()` mounts the partition named "storage" at `/spiffs`. The `format_if_mount_failed` flag formats the partition if it is empty, as on a first boot.

3. `init_mdns()` registers the name "thermostat" and announces the web server.

4. `dht_read()` does the full exchange with the sensor: start signal, answer, 40 bits and checksum. It returns the temperature, the humidity and a flag that says whether the reading is valid.

5. `start_webserver()` registers four handlers. Three answer the API: they read or change the state under the mutex and reply with JSON. The fourth sends files from SPIFFS.

6. `sensor_task()` runs on core 1, away from the Wi-Fi tasks on core 0. Every 2 seconds it reads the DHT22. After a valid reading it updates the state and runs the thermostat logic. After 5 failed readings in a row it switches the heater off. Until the first good reading the status reports `"temp": null` (cJSON writes `NAN` as null), and the page shows "--.-".

## Building and Flashing

<InArticleAd />


<Steps>
1. Create the project directory and place all files according to the project structure above:
   ```bash
   mkdir -p esp32-thermostat/main
   mkdir -p esp32-thermostat/spiffs_data
   ```

2. Set the target chip:
   ```bash
   cd esp32-thermostat
   ```

   Navigate to **Thermostat Configuration** and enter your Wi-Fi SSID and password.

   ```bash

   ```

   ```bash
       0x70000 spiffs_data spiffs_image.bin
   ```

6. Flash the firmware and SPIFFS image together:
   ```bash
   idf.py -p /dev/ttyUSB0 flash
   esptool.py --port /dev/ttyUSB0 write_flash 0x190000 spiffs_image.bin
   ```
   On macOS use `/dev/cu.usbserial-XXXX`. On Windows use `COM3` or your port.

7. Start the serial monitor:
   ```bash
   idf.py -p /dev/ttyUSB0 monitor
   ```

8. Watch the boot log:

### Check it

A thermostat is right when its reading is right and its relay obeys the band. Check three things before you leave it running:

1. **The reading.** Put a second thermometer next to the DHT22 for 10 minutes, away from the ESP32 (the chip warms the air near it). The DHT22 is specified to about ±0.5 °C, so the two should agree within about 1 °C. A larger difference means a poor sensor or a sensor placed in warm air.
2. **The band.** With the setpoint at 23.0 °C, warm the sensor slowly in your hand and watch the log: the relay must turn off only above 23.5 °C, and on again only below 22.5 °C as it cools. A relay that changes inside the band means the hysteresis is not in effect.
3. **The failure.** With the relay on in auto mode, pull the data wire. Within about 10 seconds the log must show `No valid reading for 10 s: heater off` and the relay must release. Put the wire back and check that control resumes.

### Troubleshooting

| Problem | Solution |
|---------|----------|
| `thermostat.local` does not resolve | Use the IP address printed in the boot log. On Windows, install Bonjour Print Services. |
| DHT read failures on every cycle | Check wiring: data pin to GPIO4, 4.7k pull-up to 3.3V. Verify the sensor is a DHT22 (not DHT11, which has a different data format). |
| SPIFFS mount fails | Verify `partitions.csv` matches the offsets used in `spiffsgen.py` and `write_flash`. Run `idf.py erase-flash` and reflash. |
| Web page loads but shows "--.-" | Check the browser console for fetch errors. Ensure the ESP32 and your device are on the same network. |
| Relay chatters rapidly | Increase `HYSTERESIS` from 0.5 to 1.0. If the sensor readings are noisy, add a software moving average filter. |

:::tip[Instrument it]
A device with its own REST API can be watched with no cloud at all: a browser on the local network reads the live values and changes a setpoint. That suits a machine on a closed factory network or a site with no internet. The device keeps control and its limits in its own firmware, and the network is only a way to see and to adjust. Give the readings and the settings clear addresses, and the device is ready to [join a wider system](/education/iot-systems/) later, such as a broker you run, for records and alerts across sites.
:::

## Exercises

<InArticleAd />


1. **Add a temperature history endpoint.** Keep the last 60 readings (2 minutes at 2-second intervals) in a circular buffer. Add `GET /api/history`, which returns them as a JSON array of objects with `timestamp` and `temp`; take the timestamps from `esp_timer_get_time()` as seconds since boot. Show the history in the web UI as a bar chart of CSS bars (no charting library).

2. **Persist the setpoint in NVS.** The setpoint returns to 23.0 C at every reboot. Save it in NVS when it changes, as in the touch dimmer, and restore it at boot. Do not write flash on every 0.5 C press while the user holds the button: use a 3-second timer that writes only after the user stops adjusting.

3. **Add OTA-updateable web UI.** Embed the HTML file in the firmware as a binary blob with `EMBED_FILES` in CMakeLists.txt, so there is no separate SPIFFS flash step, and serve it from the embedded data. Compare this with SPIFFS: a larger firmware binary, a simpler flash process, no file system overhead.

4. **Implement a moving average filter for the DHT22.** Raw readings can jump by 0.3 to 0.5 C between reads (noise and quantization). Average the last 5 valid readings, kept in a circular buffer, before updating `state.temperature`. Compare filtered and raw readings in the serial log, and watch the filter reduce relay switching near the band edges.

## Summary

<InArticleAd />


- The HTTP server calls one handler for each method and URI. GET reads the state, POST changes it, and the data is JSON.
- A handler must check the length, the names and the types of what it receives, and answer with an error when they are wrong.
- SPIFFS keeps the web page in its own flash partition, and mDNS gives the device a name on the local network.
- The DHT22 sends bits as pulse lengths, and its checksum rejects a reading that an interrupt disturbed.
- Hysteresis gives two switching points, so that noise cannot switch the relay at every reading.
- The thermostat logic runs in the firmware. The web page shows and adjusts it, and the thermostat continues without the network.
