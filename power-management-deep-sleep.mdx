An ESP32 with Wi-Fi on draws around 150 mA, which empties two AA batteries in less than a day. A sensor in a field that needs new batteries every day will not stay in use for long. In deep sleep the chip itself draws about 10 microamps, so a node that sleeps most of the time and wakes for a few seconds can run for months. In this lesson you put the ESP32 to sleep, wake it by a timer or a pin, and keep data across the sleep. You build a weather node for batteries, and you calculate how long the batteries last before you install it. #ESP32 #DeepSleep #LowPower

## Circuit Connections

<InArticleAd />


Connect the DHT22 sensor and a push button (simulating a rain sensor trigger) to the ESP32 on a breadboard:

| ESP32 Pin | Component | Notes |
|-----------|-----------|-------|
| GPIO 4 | DHT22 data pin | 10k pull-up resistor to 3.3V |
| GPIO 25 | Push button to GND | ext0 wake source (rain sensor trigger) |
| 3.3V | DHT22 VCC, pull-up resistor | Power supply |
| GND | DHT22 GND, button GND | Common ground |

GPIO 25 is an RTC GPIO: a pin wired to the small part of the chip that stays powered in deep sleep. Only RTC GPIOs can wake the chip. The push button stands for a rain sensor with a digital output. When pressed, it pulls GPIO 25 low, and the chip wakes at once.

To run from batteries, connect two AA batteries (3V together) to the 3.3V pin and GND. The 3.3V pin goes past the voltage regulator on the board and feeds the ESP32 directly. The chip accepts about 2.3V to 3.6V. For a supply above 3.6V, use the VIN pin, which goes through the regulator.

:::caution
When powering from batteries via the 3.3V pin, disconnect the USB cable. Running both power sources simultaneously can cause current to flow in unintended directions and damage the board or the batteries.
:::

## ESP32 Power Modes

<InArticleAd />


A chip saves power by switching parts of itself off: the more it switches off, the less current it draws, the less it remembers and the fewer things can wake it. The ESP32 has five such steps, the power modes. One part appears in every row below: the RTC (real-time clock) domain, a small section of the chip with its own timer and a little memory, which stays on when the rest is off. All currents in the table are for the chip alone, not for a whole board.

| Mode | Typical Current | What Runs | What Is Preserved | Wake Sources |
|------|----------------|-----------|-------------------|--------------|
| Active | 80 to 260 mA | Everything (CPU, Wi-Fi, BT, peripherals) | Everything | N/A (already active) |
| Modem Sleep | 15 to 30 mA | CPU, peripherals; Wi-Fi/BT radio off | RAM, CPU state | Internal (auto, DTIM based) |
| Light Sleep | 0.8 mA | RTC, ULP; CPU paused | RAM, CPU registers, peripherals | Timer, GPIO, touch, UART |
| Deep Sleep | 10 uA | RTC controller, RTC memory, RTC peripherals | RTC slow memory (8 KB) | Timer, ext0/ext1 GPIO, touch, ULP |
| Hibernation | 5 uA | RTC timer only | Nothing (except RTC timer) | Timer only |

**Active mode** is normal running. Wi-Fi transmission peaks at around 260 mA. The CPU alone, with the radios off, draws about 30 to 50 mA.

**Modem Sleep** is done by the Wi-Fi driver itself while the chip is connected to an access point. The radio switches off between the beacons of the access point at which waiting data is announced (the DTIM beacons). Your code does nothing for it.

**Light Sleep** pauses the CPU and keeps all of RAM. When the chip wakes, the program continues at the instruction where it stopped, like a film after the pause button.

**Deep Sleep** is the mode for a battery node. The main CPUs, most of the RAM and all digital peripherals lose power; only the RTC controller, the RTC slow memory (8 KB) and, if used, the ULP coprocessor stay on. Waking is a reset: the bootloader runs and `app_main()` starts from its first line, like switching a computer off and on, not like the pause button. Anything that must survive has to be in RTC memory.

**Hibernation** leaves only the RTC timer on, for about 5 uA. Only the timer can wake the chip, and RTC memory is lost. Use it when the node needs nothing but a timed wake.

The drawing shows what can wake the chip from deep sleep. Each source is explained below.

```text
                   ┌────────────────┐
 Timer ───────────>│ RTC controller │
 ext0, one pin ───>│ stays on at    │
 ext1, pin mask ──>│ about 10 uA    ├──> Wake = reset:
 Touch pad ───────>│ and keeps 8 KB │    app_main()
 ULP program ─────>│ of RTC memory  │    starts again
                   └────────────────┘
```

## Deep Sleep Configuration

<InArticleAd />


Deep sleep needs two steps in code. You enable one or more wake sources, then you call `esp_deep_sleep_start()`. This function never returns, because the chip wakes by a reset and runs `app_main()` from the beginning.

```c
#include "esp_sleep.h"

/* Enable a 5-minute timer wake source */
uint64_t sleep_time_us = 5 * 60 * 1000000ULL;  /* 5 minutes in microseconds */
esp_sleep_enable_timer_wakeup(sleep_time_us);

/* Enter deep sleep (this call never returns) */
esp_deep_sleep_start();
```

After the wake the ESP32 behaves as if just switched on: every variable in ordinary RAM has its starting value again, Wi-Fi is not started and no FreeRTOS task exists, so `app_main()` must set everything up each time. Deep sleep firmware is a program that runs once from top to bottom: start, do the work, save what must survive, sleep.

### Boot Count Example

To see that deep sleep works, count how many times the device has started. The attribute `RTC_DATA_ATTR` places a variable in RTC slow memory, which keeps its contents through a deep sleep reset:

```c
#include <stdio.h>
#include "esp_sleep.h"
#include "esp_log.h"

static const char *TAG = "deep_sleep_demo";

/* This variable survives deep sleep resets */
RTC_DATA_ATTR static int s_boot_count = 0;

void app_main(void)
{
    s_boot_count++;
    ESP_LOGI(TAG, "Boot count: %d", s_boot_count);

    /* Do useful work here... */

    /* Configure timer wake: 10 seconds */
    esp_sleep_enable_timer_wakeup(10 * 1000000ULL);

    ESP_LOGI(TAG, "Entering deep sleep for 10 seconds");
    esp_deep_sleep_start();
    /* Execution never reaches here */
}
```

Flash it and open the serial monitor: the boot count rises with every wake, 1, 2, 3 and so on. Without `RTC_DATA_ATTR` it would start from 0 every time, because ordinary RAM is lost in deep sleep.

## Wake Sources

<InArticleAd />


A sleeping node wakes for one of two reasons: it is time for a reading, or something happened. You can enable several wake sources together; the chip wakes when any one fires, and `esp_sleep_get_wakeup_cause()` then tells you which.

### Timer Wake

The timer is the usual source for a node that reports at a fixed interval. You give the sleep time in microseconds:

```c
/* Wake after 5 minutes */
esp_sleep_enable_timer_wakeup(5 * 60 * 1000000ULL);
```

The RTC timer runs from a simple internal oscillator, not from a crystal, so it can be wrong by a few percent. If the node must report at exact times, read the time from a network time (NTP) server while it is awake and correct the next sleep time.

### ext0 Wake (Single GPIO)

The ext0 source watches one RTC GPIO and wakes the chip when that pin is at the level you name:

```c
/* Wake when GPIO 25 goes LOW (button pressed, pulled to GND) */
esp_sleep_enable_ext0_wakeup(GPIO_NUM_25, 0);
```

The second parameter is the trigger level: `0` for low, `1` for high. Only RTC GPIOs work as ext0 wake sources. On the ESP32, these are GPIOs 0, 2, 4, 12, 13, 14, 15, 25, 26, 27, and 32 to 39 (GPIO 37 and 38 are not brought out on the DevKitC).

A pin with only a button on it has no defined level while the button is open, and would wake the chip at random; a pull-up resistor holds it high. The ordinary GPIO circuits are off in deep sleep, so switch on the pull-up of the RTC part:

```c
/* Enable internal pull-up on GPIO 25 so it reads HIGH when the button is not pressed */
esp_sleep_pd_config(ESP_PD_DOMAIN_RTC_PERIPH, ESP_PD_OPTION_ON);
rtc_gpio_pullup_en(GPIO_NUM_25);
rtc_gpio_pulldown_dis(GPIO_NUM_25);
```

The call to `esp_sleep_pd_config()` with `ESP_PD_OPTION_ON` keeps the RTC peripherals powered in deep sleep. The internal pull resistors need this. It adds a few microamps to the sleep current.

### ext1 Wake (Multiple GPIOs)

The ext1 source watches several RTC GPIOs together. You give a bitmask, a number in which each 1 bit selects one pin, and a trigger mode:

```c
/* Wake when ANY of GPIO 25 or GPIO 26 goes HIGH */
uint64_t ext1_mask = (1ULL << GPIO_NUM_25) | (1ULL << GPIO_NUM_26);
esp_sleep_enable_ext1_wakeup(ext1_mask, ESP_EXT1_WAKEUP_ANY_HIGH);
```

Two trigger modes are available on the original ESP32 (`ESP_EXT1_WAKEUP_ANY_LOW` exists only on newer chips such as the ESP32-S3):

- `ESP_EXT1_WAKEUP_ALL_LOW`: Wake only when all specified pins are low simultaneously
- `ESP_EXT1_WAKEUP_ANY_HIGH`: Wake when any one of the specified pins goes high

After waking from ext1, you can determine which specific pin triggered the wake:

```c
uint64_t wakeup_pin_mask = esp_sleep_get_ext1_wakeup_status();
if (wakeup_pin_mask & (1ULL << GPIO_NUM_25)) {
    ESP_LOGI(TAG, "Wake triggered by GPIO 25");
}
if (wakeup_pin_mask & (1ULL << GPIO_NUM_26)) {
    ESP_LOGI(TAG, "Wake triggered by GPIO 26");
}
```

### Touch Pad Wake

The ESP32's capacitive touch pins can wake the chip from deep sleep. First, configure the touch pad and set a threshold, then enable touch wake:

```c
#include "driver/touch_pad.h"

/* Initialize touch pad */
touch_pad_init();
touch_pad_config(TOUCH_PAD_NUM8, 0);  /* GPIO 33 */
touch_pad_set_thresh(TOUCH_PAD_NUM8, 400);

/* Enable touch pad wake */
esp_sleep_enable_touchpad_wakeup();
```

After waking, call `esp_sleep_get_touchpad_wakeup_status()` to determine which touch pad triggered the wake.

### ULP Wake

The ULP (Ultra Low Power) coprocessor can also wake the main processor. The ULP coprocessor section below shows how.

## Determining the Wake Cause

<InArticleAd />


Every wake starts the same program from the top, so the firmware must first ask why it woke. The answer decides what to do: a timer wake means "read the sensors and publish", and a GPIO wake means "it has started to rain".

```c
void handle_wakeup_reason(void)
{
    esp_sleep_wakeup_cause_t cause = esp_sleep_get_wakeup_cause();

    switch (cause) {
        case ESP_SLEEP_WAKEUP_TIMER:
            ESP_LOGI(TAG, "Woke from timer (periodic reading)");
            break;

        case ESP_SLEEP_WAKEUP_EXT0:
            ESP_LOGI(TAG, "Woke from ext0 GPIO (rain sensor triggered)");
            break;

        case ESP_SLEEP_WAKEUP_EXT1: {
            uint64_t pins = esp_sleep_get_ext1_wakeup_status();
            ESP_LOGI(TAG, "Woke from ext1, pin mask: 0x%llx",
                     (unsigned long long)pins);
            break;
        }

        case ESP_SLEEP_WAKEUP_TOUCHPAD: {
            int pad = esp_sleep_get_touchpad_wakeup_status();
            ESP_LOGI(TAG, "Woke from touch pad %d", pad);
            break;
        }

        case ESP_SLEEP_WAKEUP_ULP:
            ESP_LOGI(TAG, "Woke from ULP coprocessor");
            break;

        case ESP_SLEEP_WAKEUP_UNDEFINED:
        default:
            ESP_LOGI(TAG, "Not a deep sleep wake (cold boot or reset)");
            break;
    }
}
```

The case `ESP_SLEEP_WAKEUP_UNDEFINED` is the first start after flashing or after the power was connected: the chip did not wake from sleep. On such a cold start you may want to calibrate once or send a "device online" message.

## RTC Memory

<InArticleAd />


Because every wake is a reset, ordinary variables forget everything. RTC slow memory is the exception, like a notebook by the bed: 8 KB of RAM that the RTC domain keeps powered through a deep sleep reset. It is wiped when the power is removed (new batteries) or new firmware is flashed. Two attributes place a variable there.

### RTC_DATA_ATTR

A variable marked `RTC_DATA_ATTR` lives in RTC slow memory. It gets its starting value at power-on, like a normal static variable, and then keeps its value from one deep sleep to the next.

```c
RTC_DATA_ATTR static int s_boot_count = 0;
RTC_DATA_ATTR static float s_last_temperature = 0.0f;
RTC_DATA_ATTR static float s_last_humidity = 0.0f;
RTC_DATA_ATTR static int64_t s_last_publish_time = 0;
RTC_DATA_ATTR static uint32_t s_total_messages_sent = 0;
```

### RTC_NOINIT_ATTR

A variable marked `RTC_NOINIT_ATTR` is also in RTC slow memory, but nothing ever gives it a starting value, so it keeps its value through a deep sleep reset, a software reset and a brownout reset (caused by a supply voltage that fell too low). Only removing the power or erasing the flash clears it. Use it to count crashes:

```c
RTC_NOINIT_ATTR static int s_crash_count;
RTC_NOINIT_ATTR static int s_brownout_count;

void app_main(void)
{
    esp_reset_reason_t reason = esp_reset_reason();
    if (reason == ESP_RST_PANIC) {
        s_crash_count++;
        ESP_LOGW(TAG, "Crash detected! Total crashes: %d", s_crash_count);
    } else if (reason == ESP_RST_BROWNOUT) {
        s_brownout_count++;
        ESP_LOGW(TAG, "Brownout detected! Total brownouts: %d", s_brownout_count);
    }
}
```

Because nothing gives these variables a starting value, they hold random values at the first power-on. To detect that first start, store a known number (a "magic number") beside your data. If the number is not there, the memory is new:

```c
#define RTC_MAGIC 0xDEADBEEF

RTC_NOINIT_ATTR static uint32_t s_magic;
RTC_NOINIT_ATTR static int s_crash_count;

void app_main(void)
{
    if (s_magic != RTC_MAGIC) {
        /* First boot after power-on: initialize */
        s_magic = RTC_MAGIC;
        s_crash_count = 0;
    }
    /* Now s_crash_count is valid */
}
```

### Practical Uses for RTC Memory

RTC memory has only 8 KB, so keep small things in it:

- Boot and message counters
- The last sensor readings, to see a fast change
- The time of the last successful publish
- The Wi-Fi channel and BSSID, for a faster connection (see "Reducing Active Time")
- Error counters, so that repeated failures can lead to a longer sleep
- The step reached in a task that takes several wakes

## ULP Coprocessor

<InArticleAd />


Suppose the node must notice an event within a fraction of a second. A main processor that woke every 100 ms to look would empty the battery in days. The ESP32 has a second, very small processor for this: the Ultra Low Power (ULP) coprocessor. It runs while the main cores are in deep sleep, draws only about 150 uA while it runs, and can use the RTC GPIOs, the RTC I2C controller, the ADC and RTC slow memory. Like a night guard who wakes the staff only when something happens, it watches a pin or a sensor and wakes the main processor only when a condition is met.

### ULP Programming Options

There are two kinds of ULP:

- **ULP FSM (Finite State Machine):** the original ULP, programmed in its own assembly language. It is in every ESP32 chip.
- **ULP RISC-V:** a newer coprocessor that is programmed in C. It is only in the ESP32-S2 and ESP32-S3.

We use the original ESP32, so we use the ULP FSM. Its language is small, about 20 instructions.

### ULP Assembly Program: GPIO Monitor

The ULP program below reads GPIO 25 (which the RTC part calls RTC GPIO 6) and wakes the main processor when the pin is LOW. The program runs once from `entry` to `halt` each time the ULP timer starts it. In the code, `r0` and `r3` are registers of the ULP, `ld` loads a value from memory and `st` stores one:

```asm
/* ulp/monitor_gpio.S
 *
 * ULP program to monitor RTC GPIO 6 (GPIO 25).
 * When the pin reads LOW, the ULP wakes the main processor.
 */

#include "soc/rtc_cntl_reg.h"
#include "soc/rtc_io_reg.h"
#include "soc/soc_ulp.h"

    /* Define the GPIO to monitor */
    .set gpio_num, 6          /* RTC GPIO 6 = GPIO 25 */

    .bss
    .global gpio_state
gpio_state:
    .long 0                   /* Shared variable: current GPIO state */

    .global wake_count
wake_count:
    .long 0                   /* How many times the ULP has checked */

    .text
    .global entry
entry:
    /* Increment the check counter */
    move r3, wake_count
    ld r0, r3, 0
    add r0, r0, 1
    st r0, r3, 0

    /* Read the RTC GPIO pin */
    READ_RTC_REG(RTC_GPIO_IN_REG, RTC_GPIO_IN_NEXT_S + gpio_num, 1)

    /* Store the current state in shared memory */
    move r3, gpio_state
    st r0, r3, 0

    /* If the pin is LOW (0), wake the main processor */
    jumpr wake_up, 1, lt

    /* Pin is HIGH: go back to sleep, check again after the ULP timer fires */
    halt

wake_up:
    /* Signal the main processor to wake */
    wake
    halt
```

The macro `READ_RTC_REG` reads the pin. The program stores the result in `gpio_state`, a variable that the main processor can read too, and gives the `wake` instruction if the pin is LOW. The `halt` instruction stops the ULP until its timer starts it again. The main code sets the period of that timer.

### Loading and Running the ULP from Main Code

The main processor loads the ULP binary, configures the ULP timer period, and starts the ULP before entering deep sleep:

```c
#include "esp_sleep.h"
#include "ulp.h"
#include "ulp_main.h"  /* Generated by the build system */
#include "driver/rtc_io.h"
#include "soc/rtc.h"

/* ULP binary, embedded by the build system */
extern const uint8_t ulp_main_bin_start[] asm("_binary_ulp_main_bin_start");
extern const uint8_t ulp_main_bin_end[]   asm("_binary_ulp_main_bin_end");

static void init_ulp_program(void)
{
    /* Configure GPIO 25 as RTC GPIO input with pull-up */
    rtc_gpio_init(GPIO_NUM_25);
    rtc_gpio_set_direction(GPIO_NUM_25, RTC_GPIO_MODE_INPUT_ONLY);
    rtc_gpio_pullup_en(GPIO_NUM_25);
    rtc_gpio_pulldown_dis(GPIO_NUM_25);

    /* Load the ULP binary into RTC slow memory */
    esp_err_t err = ulp_load_binary(0, ulp_main_bin_start,
        (ulp_main_bin_end - ulp_main_bin_start) / sizeof(uint32_t));
    ESP_ERROR_CHECK(err);

    /* Set the ULP wakeup period: check every 100 ms */
    ulp_set_wakeup_period(0, 100000);  /* microseconds */

    /* Enable ULP wake source */
    esp_sleep_enable_ulp_wakeup();

    /* Start the ULP program (entry point label) */
    ESP_ERROR_CHECK(ulp_run(&ulp_entry - RTC_SLOW_MEM));
}
```

`ulp_set_wakeup_period()` sets how often the ULP runs its program. With 100 ms, the ULP draws about 150 uA for a short moment every 100 ms, which adds roughly 1 to 2 uA to the average sleep current; a shorter period adds more, in proportion.

### ULP CMakeLists.txt

To build ULP assembly programs, update the `main/CMakeLists.txt`:

```cmake
idf_component_register(SRCS "main.c"
                       INCLUDE_DIRS "."
                       REQUIRES ulp)

set(ulp_app_name ulp_main)
set(ulp_sources "ulp/monitor_gpio.S")
set(ulp_exp_dep_srcs "main.c")

ulp_embed_binary(${ulp_app_name} "${ulp_sources}" "${ulp_exp_dep_srcs}")
```

You also need to enable the ULP in `sdkconfig` or menuconfig. Navigate to **Component config, Ultra Low Power (ULP) Co-processor**, enable **Enable Ultra Low Power (ULP) Co-processor**, and set **ULP Co-processor type** to **ULP FSM**.

### Reading ULP Shared Variables from Main Code

After waking from a ULP trigger, the main code can read the shared variables that the ULP program stored in RTC slow memory:

```c
void app_main(void)
{
    esp_sleep_wakeup_cause_t cause = esp_sleep_get_wakeup_cause();

    if (cause == ESP_SLEEP_WAKEUP_ULP) {
        /* Read the ULP's shared variables */
        uint32_t gpio_val = ulp_gpio_state & 0xFFFF;
        uint32_t checks = ulp_wake_count & 0xFFFF;
        ESP_LOGI(TAG, "ULP wake: gpio_state=%lu, check_count=%lu",
                 (unsigned long)gpio_val, (unsigned long)checks);
    }

    /* ... rest of app_main ... */
}
```

The `& 0xFFFF` mask is necessary because ULP variables are 32 bits wide in the memory map but the ULP itself only writes the lower 16 bits. The upper 16 bits hold the register number and the address of the ULP instruction that stored the value.

## Power Budget Calculation

<InArticleAd />


A battery holds a fixed amount of charge, as a tank holds water. The node draws charge quickly for a few seconds, then very slowly for minutes, and what empties the tank is the average flow over a whole cycle: add the charge of each phase (current times time) and divide by the length of the cycle:

```
average_current = (active_time * active_current + sleep_time * sleep_current) / total_cycle_time
```

Times are in seconds and currents in mA, so the charge of a phase is in mA s (milliamp seconds). The drawing shows the current through one cycle of 5 minutes (300 s). It is not to scale: the sleep takes 98% of the time.

```text
 Current
 (mA)
  150 │             ┌─────────────────┐
      │             │  Wi-Fi + MQTT   │
      │  Init       │                 │
   40 ├──────┐      │                 │  Shutdown
   30 │      │      │                 └──────┐
   20 │      └──────┘                        │
      │       Sensor                         │  Deep sleep
 0.01 │                                      └────────────
      └──────┬──────┬─────────────────┬──────┬───────────►
      0     0.5    1.0               5.0    5.5      300 s
                           Time
```

### Example: Weather Node with 5-Minute Interval

One cycle of the weather node has these phases. The sleep current is that of the chip alone, 10 uA, which is 0.01 mA:

| Phase | Duration | Current Draw |
|-------|----------|-------------|
| Wake and initialize | 0.5 s | 40 mA |
| Read DHT22 sensor | 0.5 s | 20 mA |
| Wi-Fi connect and MQTT publish | 4 s | 150 mA |
| Wi-Fi disconnect and prepare sleep | 0.5 s | 30 mA |
| Deep sleep | 294.5 s | 0.01 mA |

The node is awake for 5.5 seconds. The charge it uses while awake is

$$
0.5 \times 40 + 0.5 \times 20 + 4 \times 150 + 0.5 \times 30 = 645\ \text{mA s}
$$

which is an average of about 117 mA over the 5.5 seconds. The sleep uses 294.5 s × 0.01 mA = 2.945 mA s. The few seconds awake use more than 200 times the charge of the five minutes asleep.

```
average_current = (645 + 294.5 * 0.01) / 300
               = (645 + 2.945) / 300
               = 647.945 / 300
               = 2.16 mA
```

Two AA alkaline batteries in series hold roughly 2500 mAh: they can give 2500 mA for one hour, or 1 mA for 2500 hours. Divide the capacity by the average current to get the battery life:

```
battery_life_hours = capacity_mAh / average_current_mA
                   = 2500 / 2.16
                   = 1157 hours
                   = 48.2 days
                   ~ 1.6 months
```

### Extending Battery Life

Almost all the charge goes to the time awake, so there are two things to change: wake less often, and stay awake for a shorter time. Start with the wake interval. Each row uses the same 5.5 s awake at an average of 117 mA, and 0.01 mA asleep. Twice the interval gives about half the average current:

| Wake Interval | Average Current | Battery Life (2x AA) |
|---------------|-----------------|---------------------|
| 1 minute | 10.8 mA | 9.7 days |
| 5 minutes | 2.16 mA | 48 days |
| 15 minutes | 0.73 mA | 143 days |
| 30 minutes | 0.37 mA | 283 days |
| 60 minutes | 0.19 mA | 1.5 years |

All these figures are for a bare ESP32 module that sleeps at 10 uA. On a development board the regulator, the USB chip and the power LED stay on while the chip sleeps, drawing 5 mA or more. At 5 mA asleep the 5 minute node lasts about 15 days, not 48, and a longer interval hardly helps, because the sleep now uses most of the charge. Measure the sleep current of what you really power.

## Reducing Active Time

<InArticleAd />


The second thing to change is the time awake, most of it the Wi-Fi connection. From nothing it takes 3 to 6 seconds: the chip searches every channel for the access point, then asks the router for an IP address (DHCP). The node knew both answers at its last wake; if it remembers them, the connection takes under 1 second.

### Store Wi-Fi Channel and BSSID

Normally the ESP32 scans all channels to find your access point. If you store the channel and the BSSID (the MAC address of the access point) in RTC memory, the next connection needs no scan:

```c
RTC_DATA_ATTR static uint8_t s_wifi_channel = 0;
RTC_DATA_ATTR static uint8_t s_wifi_bssid[6] = {0};
RTC_DATA_ATTR static bool s_wifi_info_valid = false;

static void wifi_init_fast(void)
{
    esp_netif_init();
    esp_event_loop_create_default();
    esp_netif_create_default_wifi_sta();

    wifi_init_config_t cfg = WIFI_INIT_CONFIG_DEFAULT();
    esp_wifi_init(&cfg);

    wifi_config_t wifi_config = {
        .sta = {
            .ssid = WIFI_SSID,
            .password = WIFI_PASSWORD,
            .threshold.authmode = WIFI_AUTH_WPA2_PSK,
        },
    };

    if (s_wifi_info_valid) {
        /* Fast reconnect: specify channel and BSSID directly */
        wifi_config.sta.channel = s_wifi_channel;
        memcpy(wifi_config.sta.bssid, s_wifi_bssid, 6);
        wifi_config.sta.bssid_set = true;
        ESP_LOGI(TAG, "Fast Wi-Fi connect: channel %d", s_wifi_channel);
    }

    esp_wifi_set_mode(WIFI_MODE_STA);
    esp_wifi_set_config(WIFI_IF_STA, &wifi_config);
    esp_wifi_start();
}
```

After a successful connection, save the channel and BSSID for next time:

```c
/* In the WIFI_EVENT_STA_CONNECTED handler */
wifi_event_sta_connected_t *event = (wifi_event_sta_connected_t *)event_data;
s_wifi_channel = event->channel;
memcpy(s_wifi_bssid, event->bssid, 6);
s_wifi_info_valid = true;
ESP_LOGI(TAG, "Saved Wi-Fi info: channel %d", s_wifi_channel);
```

If the fast connect fails (the access point changed channel or rebooted), clear the saved info and fall back to a full scan:

```c
/* In the WIFI_EVENT_STA_DISCONNECTED handler */
if (s_wifi_info_valid && retry_count > 1) {
    s_wifi_info_valid = false;  /* Force full scan on next boot */
    ESP_LOGW(TAG, "Fast connect failed, will do full scan next time");
}
```

### Use a Static IP Address

Asking the router for an address by DHCP takes 1 to 3 seconds. If your network allows it, give the node a fixed (static) IP address, outside the range that the router gives to other devices:

```c
esp_netif_t *sta_netif = esp_netif_create_default_wifi_sta();

/* Stop DHCP client */
esp_netif_dhcpc_stop(sta_netif);

/* Configure static IP */
esp_netif_ip_info_t ip_info = {0};
IP4_ADDR(&ip_info.ip, 192, 168, 1, 200);
IP4_ADDR(&ip_info.gw, 192, 168, 1, 1);
IP4_ADDR(&ip_info.netmask, 255, 255, 255, 0);
esp_netif_set_ip_info(sta_netif, &ip_info);

/* Set DNS server manually (required to resolve the broker hostname) */
esp_netif_dns_info_t dns_info;
IP4_ADDR(&dns_info.ip.u_addr.ip4, 8, 8, 8, 8);
dns_info.ip.type = ESP_IPADDR_TYPE_V4;
esp_netif_set_dns_info(sta_netif, ESP_NETIF_DNS_MAIN, &dns_info);
```

### Combined Savings

With the stored channel and BSSID and a static IP, the connection phase falls from 4 seconds to about 0.5 to 1 second. The power budget with a connection time of 1 second:

| Phase | Duration | Current Draw |
|-------|----------|-------------|
| Wake, sensor read, fast connect, MQTT publish | 2 s | 120 mA |
| Deep sleep (5-minute interval) | 298 s | 0.01 mA |

```
average_current = (2 * 120 + 298 * 0.01) / 300
               = (240 + 2.98) / 300
               = 0.81 mA
```

Battery life: $2500 / 0.81 \approx 3086\ \text{hours} \approx 129\ \text{days}$, or about 4 months. That is more than twice the 48 days of the first budget, at the same 5 minute interval.

## Complete Firmware

<InArticleAd />


This firmware joins the parts of the lesson: deep sleep with a timer and a GPIO as wake sources, RTC memory, the fast Wi-Fi connection and MQTT publishing. It uses ext0 for the rain pin. The ULP program above is another way to watch that pin and is not part of this firmware.

```c
/* main.c -- Battery-Powered Weather Node with Deep Sleep
 *
 * ESP-IDF v5.x project.
 * Wakes from deep sleep on timer (5 min) or GPIO (rain sensor on GPIO 25).
 * Reads a DHT22 sensor, connects to Wi-Fi (fast reconnect),
 * publishes data via MQTT, and returns to deep sleep.
 * Tracks boot count and message count in RTC memory.
 * The ext0 wake source watches the rain sensor GPIO during sleep.
 */

#include <string.h>
#include <stdlib.h>
#include <stdio.h>
#include "freertos/FreeRTOS.h"

static const char *TAG = "weather_node";

#define MQTT_BROKER_URI CONFIG_MQTT_BROKER_URI
#define MQTT_USERNAME   CONFIG_MQTT_USERNAME
#define MQTT_PASSWORD   CONFIG_MQTT_PASSWORD

#define TOPIC_WEATHER   "weather/station1/data"
#define TOPIC_STATUS    "weather/station1/status"
#define TOPIC_ALERT     "weather/station1/alert"

/* Pin definitions */

#define RAIN_GPIO       GPIO_NUM_25

/* Sleep configuration */
#define DEFAULT_SLEEP_TIME_SEC  (5 * 60)   /* 5 minutes */
#define MQTT_TIMEOUT_MS         8000       /* Max wait for MQTT publish */
#define WIFI_TIMEOUT_MS         10000      /* Max wait for Wi-Fi connection */
#define MAX_WIFI_RETRY          3

/* ---------- RTC memory (persists across deep sleep) ---------- */

RTC_DATA_ATTR static int s_boot_count = 0;
RTC_DATA_ATTR static uint32_t s_messages_sent = 0;
RTC_DATA_ATTR static float s_last_temperature = 0.0f;
RTC_DATA_ATTR static float s_last_humidity = 0.0f;
RTC_DATA_ATTR static uint8_t s_wifi_channel = 0;
RTC_DATA_ATTR static uint8_t s_wifi_bssid[6] = {0};
RTC_DATA_ATTR static bool s_wifi_info_valid = false;

/* ---------- Global state ---------- */

static EventGroupHandle_t s_wifi_event_group;
#define WIFI_CONNECTED_BIT BIT0
#define WIFI_GOT_IP_BIT    BIT1
#define WIFI_FAIL_BIT      BIT2

static esp_mqtt_client_handle_t s_mqtt_client = NULL;
static volatile bool s_mqtt_connected = false;
static volatile bool s_mqtt_published = false;
static int s_wifi_retry_count = 0;

/* ---------- DHT22 sensor reading ---------- */

/* Simplified DHT22 bit-banging driver.
 * For production, use a dedicated component from the ESP-IDF registry. */

static bool dht22_read(float *temperature, float *humidity)
{
    uint8_t data[5] = {0};
    int bit_idx = 0;

    /* Send start signal: pull low for 2 ms, then release */
    gpio_set_direction(DHT22_GPIO, GPIO_MODE_OUTPUT);
    gpio_set_level(DHT22_GPIO, 0);
    esp_rom_delay_us(2000);
    gpio_set_level(DHT22_GPIO, 1);
    esp_rom_delay_us(30);

    /* Switch to input and wait for sensor response */
    gpio_set_direction(DHT22_GPIO, GPIO_MODE_INPUT);

    /* Wait for sensor pull-low (response signal) */
    int timeout = 100;
    while (gpio_get_level(DHT22_GPIO) == 1 && timeout > 0) {
        esp_rom_delay_us(1);
        timeout--;
    }
    if (timeout <= 0) return false;

    /* Wait through the response low pulse (~80 us) */
    timeout = 100;
    while (gpio_get_level(DHT22_GPIO) == 0 && timeout > 0) {
        esp_rom_delay_us(1);
        timeout--;
    }

    /* Wait through the response high pulse (~80 us) */
    timeout = 100;
    while (gpio_get_level(DHT22_GPIO) == 1 && timeout > 0) {
        esp_rom_delay_us(1);
        timeout--;
    }

    /* Read 40 bits (5 bytes) of data */
    for (int i = 0; i < 40; i++) {
        /* Wait for the low period (~50 us) */
        timeout = 100;
        while (gpio_get_level(DHT22_GPIO) == 0 && timeout > 0) {
            esp_rom_delay_us(1);
            timeout--;
        }

        /* Measure the high period: >40 us = 1, <30 us = 0 */
        int high_time = 0;
        while (gpio_get_level(DHT22_GPIO) == 1 && high_time < 100) {
            esp_rom_delay_us(1);
            high_time++;
        }

        data[i / 8] <<= 1;
        if (high_time > 35) {
            data[i / 8] |= 1;
        }
        bit_idx++;
    }

    /* Verify checksum */
    uint8_t checksum = data[0] + data[1] + data[2] + data[3];
    if (checksum != data[4]) {
        ESP_LOGW(TAG, "DHT22 checksum failed: expected %d, got %d",
                 data[4], checksum);
        return false;
    }

    /* Parse humidity (data[0..1]) and temperature (data[2..3]) */
    *humidity = ((data[0] << 8) | data[1]) * 0.1f;
    int16_t temp_raw = ((data[2] & 0x7F) << 8) | data[3];
    if (data[2] & 0x80) temp_raw = -temp_raw;
    *temperature = temp_raw * 0.1f;

    return true;
}

/* ---------- Wi-Fi event handler ---------- */

static void wifi_event_handler(void *arg, esp_event_base_t event_base,
                                int32_t event_id, void *event_data)
{
    if (event_base == WIFI_EVENT) {
        if (event_id == WIFI_EVENT_STA_START) {
            esp_wifi_connect();
        } else if (event_id == WIFI_EVENT_STA_CONNECTED) {
            /* Save channel and BSSID for fast reconnect */
            wifi_event_sta_connected_t *evt =
                (wifi_event_sta_connected_t *)event_data;
            s_wifi_channel = evt->channel;
            memcpy(s_wifi_bssid, evt->bssid, 6);
            s_wifi_info_valid = true;
            ESP_LOGI(TAG, "Wi-Fi connected, channel %d", s_wifi_channel);
        } else if (event_id == WIFI_EVENT_STA_DISCONNECTED) {
            if (s_wifi_retry_count < MAX_WIFI_RETRY) {
                /* On second retry failure, invalidate fast connect data */
                if (s_wifi_retry_count >= 1 && s_wifi_info_valid) {
                    s_wifi_info_valid = false;
                    ESP_LOGW(TAG, "Fast connect failed, cleared saved info");
                }
                esp_wifi_connect();
                s_wifi_retry_count++;
                ESP_LOGW(TAG, "Wi-Fi retry %d/%d",
                         s_wifi_retry_count, MAX_WIFI_RETRY);
            } else {
                xEventGroupSetBits(s_wifi_event_group, WIFI_FAIL_BIT);
                ESP_LOGE(TAG, "Wi-Fi connection failed after %d retries",
                         MAX_WIFI_RETRY);
            }
        }
    } else if (event_base == IP_EVENT && event_id == IP_EVENT_STA_GOT_IP) {
        ip_event_got_ip_t *evt = (ip_event_got_ip_t *)event_data;
        ESP_LOGI(TAG, "Got IP: " IPSTR, IP2STR(&evt->ip_info.ip));
        s_wifi_retry_count = 0;
        xEventGroupSetBits(s_wifi_event_group, WIFI_GOT_IP_BIT);
    }
}

/* ---------- Wi-Fi initialization (fast reconnect) ---------- */

static bool wifi_init_fast(void)
{
    s_wifi_event_group = xEventGroupCreate();

    esp_netif_init();
    esp_event_loop_create_default();
    esp_netif_create_default_wifi_sta();

    wifi_init_config_t cfg = WIFI_INIT_CONFIG_DEFAULT();
    esp_wifi_init(&cfg);

    esp_event_handler_instance_register(WIFI_EVENT, ESP_EVENT_ANY_ID,
                                         &wifi_event_handler, NULL, NULL);
    esp_event_handler_instance_register(IP_EVENT, IP_EVENT_STA_GOT_IP,
                                         &wifi_event_handler, NULL, NULL);

    wifi_config_t wifi_config = {
        .sta = {
            .ssid = WIFI_SSID,
            .password = WIFI_PASSWORD,
            .threshold.authmode = WIFI_AUTH_WPA2_PSK,
        },
    };

    /* Use stored channel and BSSID for fast reconnect */
    if (s_wifi_info_valid) {
        wifi_config.sta.channel = s_wifi_channel;
        memcpy(wifi_config.sta.bssid, s_wifi_bssid, 6);
        wifi_config.sta.bssid_set = true;
        ESP_LOGI(TAG, "Fast reconnect: channel %d", s_wifi_channel);
    } else {
        ESP_LOGI(TAG, "Full Wi-Fi scan (no saved info)");
    }

    esp_wifi_set_mode(WIFI_MODE_STA);
    esp_wifi_set_config(WIFI_IF_STA, &wifi_config);

    /* Disable Wi-Fi power saving during active phase for faster throughput */
    esp_wifi_set_ps(WIFI_PS_NONE);

    esp_wifi_start();

    /* Wait for IP or failure, with timeout */
    EventBits_t bits = xEventGroupWaitBits(s_wifi_event_group,
        WIFI_GOT_IP_BIT | WIFI_FAIL_BIT,
        pdFALSE, pdFALSE,
        pdMS_TO_TICKS(WIFI_TIMEOUT_MS));

    if (bits & WIFI_GOT_IP_BIT) {
        return true;
    }

    ESP_LOGE(TAG, "Wi-Fi connection timed out or failed");
    return false;
}

static void wifi_shutdown(void)
{
    esp_wifi_disconnect();
    esp_wifi_stop();
    esp_wifi_deinit();
}

/* ---------- MQTT ---------- */

static void mqtt_event_handler(void *handler_args,
                                 esp_event_base_t base,
                                 int32_t event_id,
                                 void *event_data)
{
    esp_mqtt_event_handle_t event = event_data;

    switch ((esp_mqtt_event_id_t)event_id) {
        case MQTT_EVENT_CONNECTED:
            ESP_LOGI(TAG, "MQTT connected");
            s_mqtt_connected = true;
            break;

        case MQTT_EVENT_PUBLISHED:
            ESP_LOGI(TAG, "MQTT message published, msg_id=%d",
                     event->msg_id);
            s_mqtt_published = true;
            break;

        case MQTT_EVENT_DISCONNECTED:
            ESP_LOGW(TAG, "MQTT disconnected");
            s_mqtt_connected = false;
            break;

        case MQTT_EVENT_ERROR:
            ESP_LOGE(TAG, "MQTT error type=%d",
                     event->error_handle->error_type);
            break;

        default:
            break;
    }
}

static bool mqtt_publish_weather(float temperature, float humidity,
                                  const char *wake_reason)
{
    esp_mqtt_client_config_t mqtt_cfg = {
        .broker = {
            .address = {
                .uri = MQTT_BROKER_URI,
            },
        },
        .credentials = {
            .username = MQTT_USERNAME,
            .authentication = {
                .password = MQTT_PASSWORD,
            },
            .client_id = "esp32-weather-node",
        },
        .session = {
            .last_will = {
                .topic = TOPIC_STATUS,
                .msg = "node-offline",
                .msg_len = 12,
                .qos = 1,
                .retain = 1,
            },
        },
    };

    s_mqtt_client = esp_mqtt_client_init(&mqtt_cfg);
    esp_mqtt_client_register_event(s_mqtt_client, ESP_EVENT_ANY_ID,
                                     mqtt_event_handler, NULL);

    s_mqtt_connected = false;
    s_mqtt_published = false;
    esp_mqtt_client_start(s_mqtt_client);

    /* Wait for MQTT connection */
    int wait_ms = 0;
    while (!s_mqtt_connected && wait_ms < MQTT_TIMEOUT_MS) {
        vTaskDelay(pdMS_TO_TICKS(100));
        wait_ms += 100;
    }

    if (!s_mqtt_connected) {
        ESP_LOGE(TAG, "MQTT connection timeout");
        esp_mqtt_client_destroy(s_mqtt_client);
        return false;
    }

    /* Publish weather data */
    char payload[256];
    snprintf(payload, sizeof(payload),
             "{\"temperature\":%.1f,\"humidity\":%.1f,"
             "\"boot_count\":%d,\"msg_count\":%lu,"
             "\"wake_reason\":\"%s\"}",
             temperature, humidity,
             s_boot_count, (unsigned long)s_messages_sent,
             wake_reason);

    int msg_id = esp_mqtt_client_publish(s_mqtt_client,
                                          TOPIC_WEATHER,
                                          payload, 0, 1, 0);
    ESP_LOGI(TAG, "Published: %s (msg_id=%d)", payload, msg_id);

    /* Wait for publish acknowledgment */
    wait_ms = 0;
    while (!s_mqtt_published && wait_ms < 3000) {
        vTaskDelay(pdMS_TO_TICKS(100));
        wait_ms += 100;
    }

    /* Publish online status (retained) */
    esp_mqtt_client_publish(s_mqtt_client, TOPIC_STATUS,
                             "node-online", 0, 1, 1);
    vTaskDelay(pdMS_TO_TICKS(200));

    esp_mqtt_client_stop(s_mqtt_client);
    esp_mqtt_client_destroy(s_mqtt_client);

    return s_mqtt_published;
}

/* ---------- Wake reason handling ---------- */

static const char *get_wake_reason_string(void)
{
    esp_sleep_wakeup_cause_t cause = esp_sleep_get_wakeup_cause();

    switch (cause) {
        case ESP_SLEEP_WAKEUP_TIMER:
            return "timer";
        case ESP_SLEEP_WAKEUP_EXT0:
            return "rain_sensor";
        case ESP_SLEEP_WAKEUP_EXT1:
            return "ext1_gpio";
        case ESP_SLEEP_WAKEUP_TOUCHPAD:
            return "touchpad";
        case ESP_SLEEP_WAKEUP_ULP:
            return "ulp";
        case ESP_SLEEP_WAKEUP_UNDEFINED:
        default:
            return "cold_boot";
    }
}

/* ---------- Deep sleep configuration ---------- */

static void configure_and_enter_deep_sleep(void)
{
    /* Timer wake: 5 minutes */
    esp_sleep_enable_timer_wakeup(
        (uint64_t)DEFAULT_SLEEP_TIME_SEC * 1000000ULL);

    /* ext0 GPIO wake: rain sensor on GPIO 25, wake on LOW */
    esp_sleep_enable_ext0_wakeup(RAIN_GPIO, 0);

    /* Keep RTC peripherals on for GPIO pull-up during sleep */
    esp_sleep_pd_config(ESP_PD_DOMAIN_RTC_PERIPH, ESP_PD_OPTION_ON);

    /* Configure the RTC GPIO pull-up for the rain sensor pin */
    rtc_gpio_init(RAIN_GPIO);
    rtc_gpio_set_direction(RAIN_GPIO, RTC_GPIO_MODE_INPUT_ONLY);
    rtc_gpio_pullup_en(RAIN_GPIO);
    rtc_gpio_pulldown_dis(RAIN_GPIO);

    /* Isolate GPIO 12 to prevent flash voltage issue on some modules */
    rtc_gpio_isolate(GPIO_NUM_12);

    /* Flush UART output before sleeping */
    uart_tx_wait_idle(CONFIG_ESP_CONSOLE_UART_NUM);

    ESP_LOGI(TAG, "Entering deep sleep for %d seconds", DEFAULT_SLEEP_TIME_SEC);
    ESP_LOGI(TAG, "Wake sources: timer (%d s), GPIO %d (rain sensor)",
             DEFAULT_SLEEP_TIME_SEC, RAIN_GPIO);

    esp_deep_sleep_start();
    /* Execution never reaches here */
}

/* ---------- Entry point ---------- */

void app_main(void)
{
    s_boot_count++;
    const char *wake_reason = get_wake_reason_string();

    ESP_LOGI(TAG, "========================================");
    ESP_LOGI(TAG, "Weather Node boot #%d", s_boot_count);
    ESP_LOGI(TAG, "Wake reason: %s", wake_reason);
    ESP_LOGI(TAG, "Messages sent so far: %lu",
             (unsigned long)s_messages_sent);
    ESP_LOGI(TAG, "========================================");

    /* Initialize NVS (required for Wi-Fi) */
    esp_err_t ret = nvs_flash_init();
    if (ret == ESP_ERR_NVS_NO_FREE_PAGES ||
        ret == ESP_ERR_NVS_NEW_VERSION_FOUND) {
        nvs_flash_erase();
        nvs_flash_init();
    }

    /* Read the DHT22 sensor */
    float temperature = 0.0f;
    float humidity = 0.0f;
    bool sensor_ok = false;

    /* Give the sensor a moment to stabilize after power-up */
    vTaskDelay(pdMS_TO_TICKS(500));

    for (int attempt = 0; attempt < 3; attempt++) {
        if (dht22_read(&temperature, &humidity)) {
            sensor_ok = true;
            s_last_temperature = temperature;
            s_last_humidity = humidity;
            ESP_LOGI(TAG, "DHT22: %.1f C, %.1f%% RH",
                     temperature, humidity);
            break;
        }
        ESP_LOGW(TAG, "DHT22 read failed, attempt %d/3", attempt + 1);
        vTaskDelay(pdMS_TO_TICKS(500));
    }

    if (!sensor_ok) {
        /* Use last known values from RTC memory */
        temperature = s_last_temperature;
        humidity = s_last_humidity;
        ESP_LOGW(TAG, "Using cached values: %.1f C, %.1f%% RH",
                 temperature, humidity);
    }

    /* Connect to Wi-Fi and publish via MQTT */
    if (wifi_init_fast()) {
        if (mqtt_publish_weather(temperature, humidity, wake_reason)) {
            s_messages_sent++;
            ESP_LOGI(TAG, "Publish successful (total: %lu)",
                     (unsigned long)s_messages_sent);
        } else {
            ESP_LOGE(TAG, "MQTT publish failed");
        }
        wifi_shutdown();
    } else {
        ESP_LOGE(TAG, "Wi-Fi failed, skipping MQTT publish");
    }

    /* Enter deep sleep */
    configure_and_enter_deep_sleep();
}
```

### How the Firmware Works

The firmware runs once from top to bottom at every wake:

1. **Start and find the wake cause.** The boot count in RTC memory rises by one. On a cold start the cause is `ESP_SLEEP_WAKEUP_UNDEFINED`.

2. **Read the DHT22.** The firmware tries three times, 500 ms apart. If all three fail, it sends the last good readings from RTC memory. Note the weakness: the receiver cannot tell these old values from new ones.

3. **Connect to Wi-Fi.** If RTC memory holds a valid channel and BSSID, the ESP32 connects without a scan, in under 1 second. If the fast connection fails twice, the saved values are marked invalid and the next attempt scans.

4. **Publish by MQTT.** The readings, the boot count, the message count and the wake reason go to the weather topic as JSON, a common text format for data. A retained "online" status follows. The MQTT client is created, used and destroyed inside this one cycle.

5. **Sleep.** Two wake sources are enabled: the 5 minute timer and ext0 on GPIO 25 for the rain sensor. The RTC pull-up is switched on and the chip enters deep sleep.

A cycle takes about 2 to 6 seconds, depending on the kind of Wi-Fi connection. For the rest of the 300 seconds the chip itself draws about 10 uA.

## Measuring Current Draw

<InArticleAd />


A power budget is a prediction. Measure the real current before you trust it, and above all the sleep current, because it flows for 98% of the time. A multimeter with a microamp (uA) range is enough for deep sleep.

### Measurement Setup

<Steps>
1. Disconnect the USB cable from the ESP32 (USB draws current through the onboard UART chip even when not communicating).

2. Set your multimeter to the appropriate current range. For deep sleep measurements, use the uA (microamp) range. For active mode, use the mA (milliamp) range.

3. Connect the multimeter in series with the battery positive lead. The positive battery terminal connects to the multimeter's mA/uA input. The multimeter's COM output connects to the ESP32's 3.3V pin (or VIN, depending on your battery voltage).

4. Power on the circuit. The ESP32 starts, runs its active cycle and enters deep sleep.
</Steps>

On its uA range a multimeter has a high internal resistance and often a small fuse. The Wi-Fi burst of more than 100 mA can then reset the chip or blow the fuse. Bridge the meter with a jumper wire while the chip is awake, and remove the jumper once it sleeps.

### Expected Readings

The first four rows are for the chip alone: a bare module on its own board. The last row is for a whole development board.

| State | Expected Reading | Notes |
|-------|-----------------|-------|
| Deep sleep, chip alone | About 10 uA | The figure used in every calculation in this lesson. Keeping the RTC peripherals on for the ext0 pull-up adds a few uA, too little to change the budget |
| Deep sleep with ULP running | 15 to 150 uA | Depends on how often the ULP runs |
| Active (CPU only, no Wi-Fi) | 30 to 50 mA | Reading sensors, processing |
| Active (Wi-Fi) | 100 to 260 mA | About 100 to 160 mA while connecting, 180 to 260 mA while transmitting |
| Deep sleep, whole development board | 5 to 20 mA | Regulator, USB-to-UART chip and LEDs stay on |

:::note
On most development boards the chip sleeps at 10 uA while the parts around it draw 5 to 20 mA: 500 to 2,000 times more. If your meter shows milliamps in deep sleep, the firmware is probably correct and the board is the cause. To reach the chip figure you must remove these parts from the supply (for example cut the trace of the power LED), or use a bare ESP32 module on your own board.
:::

### Using a Current Profiler

A current profiler, such as the Nordic Power Profiler Kit II or the Joulescope, records the current against time. It shows each phase (start, sensor read, Wi-Fi scan, transmit burst, sleep) and so shows a part that does not switch off.

## Exercises

<InArticleAd />


1. **Adaptive sleep interval.** If the temperature changed by more than 2 degrees since the last reading (kept in RTC memory), sleep for 1 minute. If it has been steady for 10 readings, sleep for 15 minutes. Keep the counter in RTC memory and add the present interval to the MQTT payload, so that you can watch the change in MQTT Explorer.

2. **Light sleep between sensor read and Wi-Fi.** After reading the DHT22, enter light sleep for 100 ms before starting Wi-Fi. The program continues where it paused, so the readings in local variables are still there. Measure the current in this phase with a multimeter and compare it with the active current.

3. **ULP threshold on a light sensor.** Add a photoresistor (LDR) to an ADC input and write a ULP program that samples the light level every 500 ms in deep sleep. When the light falls below a threshold, the ULP wakes the main processor to send an alert. Publish the light level with the DHT22 data at each timed wake. Keep the threshold in RTC memory so that the main code can change it by an MQTT command.

4. **Battery voltage and low-battery mode.** Add a voltage divider (two resistors) from the battery positive terminal to an ADC1 input and read the battery voltage at the start of each wake. Publish it. Below 2.4V (two AA cells nearly empty), publish a "low-battery" alert and raise the sleep interval to 30 minutes. Keep the low-battery state in RTC memory.

## Summary

<InArticleAd />


- The ESP32 has five power modes, from a peak of 260 mA with Wi-Fi transmitting to about 5 uA in hibernation. Deep sleep, at about 10 uA for the chip alone, is the usual choice for a battery node.
- Waking from deep sleep is a reset. `app_main()` starts from its first line, and only the 8 KB of RTC slow memory keeps its contents. `RTC_DATA_ATTR` and `RTC_NOINIT_ATTR` place counters, last readings and Wi-Fi details there.
- Several wake sources can be enabled together (timer, ext0, ext1, touch pad, ULP), and `esp_sleep_get_wakeup_cause()` says which one fired. Only RTC GPIOs can wake the chip.
- The ULP coprocessor watches a pin during deep sleep for an average of only 1 to 2 uA and wakes the main processor when a condition is met.
- The power budget is the charge of each phase, added and divided by the cycle time. With a bare module, the seconds awake use nearly all of the charge: wake less often and connect faster. A 5 minute interval with the fast connection gives about 4 months on two AA cells.
- A development board draws milliamps while the chip sleeps. Measure the sleep current of what you really power before you trust any estimate.
